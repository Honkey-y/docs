## 2. 实施步骤

### 1. 补充统一人数查询

- 位置：核心 license 模块的 Service／Mapper，复用 user_info、user_enterprise_pk、enterprise_info。
- 改动：增加环境占用、企业占用及环境概览查询；只按 username=admin 排除超级管理员，不按用户 ID。直接用现有索引，不增加锁、计数器或数据表。
- 验证：跨企业去重、管理员、启用／禁用、无企业、重复及孤立关系；对照已完成的 Alpha SQL 结果。

### 2. 在现有快照和概览补字段

- 位置：REST `license/LicenseController.java`、`LicenseInternalController.java`，核心 `license/vo/LicenseOverviewVO.java`、`LicenseInternalSnapshotVO.java`。
- 改动：概览补 occupiedUsers，内部快照补 userLimitExceeded。授权字段、状态、解析和通知直接复用；`PlainJsonLicenseParser.requiredNonNegativeInteger()` 仅补必要的整数合法性，避免小数截断或越界变成 0。
- 依赖：步骤 1。
- 验证：0 不限、正数等额允许／超额拒绝、非法人数保持现有授权异常；原快照字段和 License 状态行为不变。

### 3. 创建、启用和导入前校验

- 位置：核心 `user/service/impl/UserInfoServiceImpl.java` 的 createUserDetail、modifyUserDetail、updateStatus、InvitationResetPassword；`ImportExportServiceImpl.java` 的 importData、importListData；`user/handler/UserImportExportHandler.java`。
- 改动：调用同一个人数校验方法，结合已有 DTO／解析结果算整次操作后的占用，在首个写入或导入副作用之前拒绝超额。正式导入不能只信 `/check`；用户页签最后也须先检查，额度错误不能被按页签 catch 后继续执行。
- 依赖：步骤 1；沿用原有事务及保存流程，不新增并发锁、不重构导入框架。
- 验证：98+2、98+10、默认创建启用、状态启用、受邀完善、混合增减、FULL 仅移除一个企业、企业／空间文件与 `/s/user/import/user` 列表导入。超额时整次操作未写入。

### 4. 网关补人数分支和 admin 放行

- 位置：网关 `filter/LicenseGatewayFilter.java`、`license/service/GatewayLicenseAccessChecker.java`、`license/model/LicenseSnapshot.java`、`vo/OauthVO.java` 及必要认证衔接。
- 改动：映射平台超额标志，复用原快照获取和缓存。只用平台认证返回的 username（平台已存在该字段）判断 admin，不按用户 ID；普通业务请求也要检查，不能仍只查 global。
- 登录协作：已与前端确认 `X-License-Scene: login`，仅对携带此值的精确 GET global 放行，前端同学添加，后端不修改前端。不做后端登录身份分流或新探测接口。
- 注意：现有 AccountRouteAccessFilter 会使账号前缀跳过 Token/API Key 过滤器，衔接时不能漏掉其 License 检查；路径准入不代表已认证。
- 依赖：步骤 2、前端配套发送已确认的请求头。
- 验证：真实 admin、普通用户、伪造身份头，超额／硬停／未授权，已有会话业务请求，登录头只对 global 生效；保持当前缓存和故障处理。

### 5. 补齐原型管理接口

- 位置：REST license 模块新增环境用户 Controller，核心 license 模块增加相应查询／管理方法；`UserInfoController` / `UserInfoServiceImpl` 的企业成员列表；网关 `src/main/resources/account-route-rules.txt`。
- 改动：按原型实现 summary/page/export/batch-disable；成员列表追加 licenseUsage；四个新增接口登记现有账号路由规则。管理权限和禁用保护只按 username=admin 判断。查询按用户分页后批量补企业，导出复用 Excel 工具，禁用复用现有状态、token 和缓存处理。
- 依赖：步骤 1；字段以只读原型 `src/modules/account/services/environmentUsers.ts`、`memberList.ts` 为准。
- 验证：超级管理员权限、组合筛选、单账号一行、统计不随筛选变化、导出全部匹配用户、保护超管和批量禁用；人数未知不当作 0。

## 3. 测试与完成标准

运行平台及网关对应的 License、用户状态、导入和过滤器测试；对新增预校验补必要边界测试。与前端同学使用现有原型联调请求头和接口，不编辑前端。

完成标准为规范验收项通过，尤其是整批导入超额未执行、admin 可处理问题，以及并发造成超额后普通用户会被网关限制。**不测试或承诺本次杜绝并发超额。** 实际接口补齐后复测查询和导出耗时，暂不增加业务索引。

## 4. 发布、回滚与依赖

1. 先发布平台的新增字段、人数校验和管理接口，再发布使用超额标志的网关；前端请求头由前端同学配套发布。
2. 沿用既有缓存配置，当前默认 60 秒；人数限制和解除跟随刷新。上线前核实现有 License 额度及 admin 通路。
3. 本方案无新表、索引或人数数据迁移。回滚采用原应用版本，已有真实用户状态变更不自动撤销。

登录请求头名称和值已确认，联调验证其实际发送、各入口调用及部署数据库方言。产品原文要求严格并发一致性，本次按用户后续指示暂不实施，由网关超额限制兜底。
