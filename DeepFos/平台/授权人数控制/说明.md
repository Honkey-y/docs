## 本次怎么做

在现有 License 上增加人数控制，复用授权字段、快照、网关缓存、导入处理和前端原型接口。

1. 平台统计环境占用人数，复用 `authorized_users` 判断是否超额。
2. 现有网关快照增加一个超额标志，网关沿用当前缓存，只补人数拦截和认证结果中的 `userId=1` 豁免，复用现有 `user` 请求头。
3. 创建、启用、含用户的导入，在实际变更前校验操作后的占用；整批导入超额则不执行。
4. 补齐原型需要的概览、企业人数、环境用户查询、导出和批量禁用接口。
5. 已与前端确认：登录页 global 携带 `X-License-Scene: login`，后端按此识别；前端代码由前端同学处理，本任务不改。

平台和网关开发前，分别从各自的 `jdk21` 基线新建需求分支，再开始编码，不直接在 `jdk21` 上开发。

## 本次明确不做

不调整快照架构和缓存时间，不新增探测接口，不做后端登录／恢复分流，不加事务锁、分布式锁或人数计数表，暂不新增业务索引。

按用户最新决定，允许并发校验后出现短时超额，后续网关随现有快照刷新限制普通用户，由管理员调整人数；不承诺本次杜绝并发超额。单次提交本身的超额预校验仍须完成。

## 已完成的调研

- Alpha：19,222 个用户、241 家企业，环境占用 16,700 人；现有索引下已验证统计 SQL。
- 按仅 username 排除 admin 重新验证，环境占用仍为 16,700，JOIN 查询三次计时间隔为 105／102／102 ms；包含驱动与往返开销，详情见 SQL 记录。
- 实施基线：平台 `e22c7a1e`、网关 `30bfa19`；两仓均已新建 `codex/license-user-count` 分支。前端只读原型不变。
- 2026-10-20 已完成本地后端实现：平台 40 项测试通过，网关使用现有依赖的临时过滤链验证 12 项通过；未修改前端，未增加依赖、表、索引或人数锁，未提交推送或部署。

先看[功能与技术规范](规划/功能与技术规范.md)，具体修改位置见[实施计划](代码执行计划/2026-10-19-人数授权实施计划.md)。产品原文中的并发一致性要求，本次按用户后续明确指示暂不实现。

## 开发补充

按用户最新要求，网关保持仅在 global 触发 License 校验；只补登录场景头、认证后的用户 ID 和人数超额判定，不扩展其他业务路由或平台 URL 鉴权。新增 Service 使用接口与 impl 实现类，说明性注释使用中文。

网关当前顺序为 API Key（-150）→ Token（-100）→ License（-90）。非登录场景的 global 携带相应凭据时，两个原认证流程负责写入 userId；不增加 VO 字段或 exchange 属性，前端无需新增 user 头。
