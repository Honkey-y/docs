当前事实与影响：

- 表格后端接收已解析的 DF 标签；当前类型只覆盖既有三类公式，新增类型必须同时进入保存、初始查询及引用查询。
- DFFILTER 展示查询前调用 `fetchChildMem`，因此应保留完整选中引用并按格式分支输出，不能全局取消旧转换。
- 成员匹配工具存在父子引用降为子编码的兜底；新属性链路必须严格匹配完整关系。
- 维度服务支持完整父子表达式。`local_currency` 是成员字段，年、版本等属于独立关系激活配置。
- VALUE 标准节点由维度生成，财务模型持有新旧分类规则；表格副本与财务模型在 Consolidation／Contribution、AdjTotal 和大小写匹配上存在差异。公共包需要规则对照测试，不能复制旧表格实现后宣称同源。
- 当前 UD 批量入口按子请求执行，调用方需先合并范围；UD 请求也不能假定已携带成员权限。
- 用户补充的六个预置属性已找到基础／实体成员字段映射；它们不依赖自定义 UD 列表。isBase 与 sharedMember 的查询映射可返回 Boolean，不能依据界面“数字”类型强制转换成 0／1。

## 四、按依赖顺序实施

### 1. 统一公式协议及维度数据源定位

- 修改位置：`deep-table-server` 的 `DFTypeEnum`、`BaseplateFunctionParser.parseValidateDF/parseCellData`、`DataSourceServiceImpl.getCubDataSourceMap/getDataSourceDTO`，以及 `WorkbookManageServiceImplV2` 的初始与引用查询入口。
- 具体改动：新增属性与币种类型；新增 DFEntityFilter 类型 6、fn／st；按对象类型解析模型或维度数据源；新增单项输入／结果映射，并明确未就绪引用沿用后续查询标记。不得把新增公式落入既有金额查询默认分支。
- 依赖关系：先冻结前后端载荷；必要时补维度数据源的元素关联与保存校验。最终 JSON 键名在协议确定后落文档。
- 验证方式：固定值与已解析引用值形成相同求值输入；无效类型、别名歧义、对象类型错误返回公式错误；旧标签和保存结果保持兼容。

### 2. 接入轮次级批量收集与回填

- 修改位置：`WorkbookManageServiceImplV2.mergeCubeExpress/thoroughParseCellData/querySheetBaseplateCellData` 及其引用查询回填链路。
- 具体改动：复用现有 DF 单元格映射，按公式类型分流；以数据源、关系、字段、语言、权限构造结构化分组键及结果键；当前轮次重复项共享结果，单项错误独立回填。初始和引用查询复用同一求值方法。
- 依赖关系：步骤 1；具体求值分支由步骤 3～5 接入。只有职责确实需要时才抽取一个批量求值服务，不把原大型服务拆成无边界的注入服务图。
- 验证方式：重复项只调用对应底层能力一次；不同关系、字段、语言及权限不共享；单项失败不会导致其余合法公式失效；显式刷新重新调用底层。

### 3. 新增实体筛选器函数并恢复原筛选器契约

- 修改位置：deepfos-planning/deep-table 的 DFTypeEnum、MetadataFormulaProtocol、BaseplateFunctionParser、WorkbookManageServiceImplV2；element-deep-table 的 dfMetadataFormula、dfFormulaRuntime、cellMapping 和使用态分层批查。
- 具体改动：DFFILTER 恢复两个参数，撤销 rf；新增 DFEntityFilter（t=6、fn／st），仅多版本实体维可用，其他维度明确报错。名称模式原样返回筛选器实际值，模式 2～5 复用原展示；删除独立引用字段、父级补齐和父级标签批查。缺失维度类型按服务与身份批查并复用缓存。内嵌实体函数先由后端校验并取编码，再查询 DFUD／DFCurrency。
- 依赖关系：步骤 1 的类型协议与步骤 2 的批量框架；不改变维度或财务模型源码，不搜索父级。
- 验证方式：覆盖纯子／父子、五种模式、非多版本实体报错、类型批查去重及失败、单元格与跨 Sheet 引用、内嵌 UD／币种依赖、当前选值切换和旧 DFFILTER 两参数回归；前端构建与 DeepTable 测试。

### 4. 批量读取成员属性并校验权限

- 修改位置：`DimensionBatchService.getUdValueByExpressBatch/queryDimensionMemberV3`、`DimensionApiShowUdServiceImpl` 的值转换，以及新公式对 `DimensionMemberResultUtils` 的使用位置；维度元数据通过既有接口取得。
- 具体改动：在电子表格新增六个预置字段描述与显式别名映射（规范见功能文档）；先识别预置属性，其余按自定义 UD 元数据校验。预置分支通过支持权限的成员批查合并 resultString，自定义分支复用动态表 UD 批查；两者统一完整关系键、文本转换及单元格回填。不把预置属性缺少 udList 条目当成字段不存在，也不把未匹配完整关系降为子编码。
- 权限接入：优先调用已有支持权限的成员批查，再仅对允许项读取 UD。普通成员接口若能返回完全一致的值，可在验证动态表一致性后合并查询。若必须补 UD 权限参数，记录缺口交给维度维护方，不能把修改维度 DTO 和实现列入电子表格开发任务，也不能临时绕过权限。
- 依赖关系：步骤 1～2及数据源权限来源明确；核验六个预置字段在目标接口版本和维度类型下的响应，不要求维度新增自定义 UD 元数据或 URL。
- 验证方式：与动态表对照普通／维度关联／值列表属性的返回值；覆盖六个预置字段及兼容别名、localCurrency 在非实体维不适用、同名不同父级、无效关系、未开放字段、无权限和 null／0／false；100 个混合属性公式按维度、接口及上下文合并，不保留逐公式子请求。

## 五、测试与验证计划

| 层级 | 必须证明的行为 | 验证方式 |
| --- | --- | --- |
| 二方包单元与消费验证 | VALUE 规则、模型结构隔离、完整关系、单项错误及普通 JAR 可用；包内零 I/O | 包维护方提供规则样例，最小普通 Java 工程消费并检查运行依赖 |
| 聚焦单元测试 | 完整关系不降级；零和假值保留；父级节点分类；缺父级错误；结果隔离 | 在实际改动所属模块新增聚焦测试，对外部接口使用替身并断言调用参数、次数及单项结果 |
| 后端集成 | 元数据、属性、权限、新旧维度查询链路及批次返回形态 | 在测试环境用相同请求和账号对照动态表及成员接口 |
| 前后端联调 | 字面值与引用、多层依赖、筛选器切换、保存重开 | 使用规范验收矩阵，保留请求载荷与回填结果 |
| 性能验收 | 不存在逐公式远程查询；重复项共享；刷新失效 | 100 个属性公式、多组模型币种公式，记录 HTTP 与内部查询次数、去重数、耗时 |
| 旧行为回归 | 三类旧 DF 公式和 DFFILTER 展示方式不变 | 保存旧配置后在改动版本打开、查询与刷新，并比较结果及错误 |

二方包工程由包交付方运行单元测试及普通 JAR 打包，并以 `mvn dependency:tree` 检查没有财务模型应用、Spring、HTTP、数据库或平台运行时依赖。电子表格在自身仓库运行实际受影响的聚焦测试，再执行必要构建；固定依赖版本必须能从内部 Maven 仓库取得。

```bash
# 二方包交付方：在独立公共包工程执行
mvn test package
mvn dependency:tree

# 电子表格开发：在 deep-table-server 根执行，替换实际测试类名
mvn -Dtest=实际受影响测试类 test
mvn -DskipTests package
```

当前未创建公共包工程或发布制品；artifactId 已确定为 deep-currency-resolution，groupId 与版本待冻结。上述包命令是独立工程的交付验证要求，不表示已执行。电子表格开发不执行财务模型／维度仓库改造或构建；无法运行的验证记录原因和替代证据，不将跳过写成通过。

## 六、发布、兼容与回退

1. 公共包交付方先发布不可变的正式版本，电子表格固定版本并完成联调后部署；新增规则不得通过覆盖同一发布版本更新。后端先部署支持旧协议及新公式的版本，前端完成协议联调后才启用新增公式录入与使用；沿用现有发布能力，不默认增加开关体系。
2. DFFILTER 保持两个参数及旧显示行为；DFEntityFilter 使用新增类型 6；不引入新的筛选器关系字段，既有维度接口保持兼容。
3. 已有工作簿不批量重写，新增公式随正常保存持久化；原测试三参数 DFFILTER 由用户改为两参数 DFEntityFilter，不自动批量改写。发布前保留联调工作簿原始配置及版本备份。
4. 监控新增公式错误率、缺父级／无权限错误、HTTP 和内部查询次数、重算耗时；发现错误先定位受影响公式与分组。
5. 回退前停止新增公式调用和保存，保留含新公式的原始配置；旧后端不保证识别新类型。确需回退的工作簿仅使用事先确认的旧配置备份，不能静默删除新公式或改为本位币标签。
6. 二方包版本随表格制品记录，回退表格版本同时恢复其固定依赖版本。其他服务是否升级包由各维护方自行安排，本期不以跨团队同步发版为前提。

## 八、完成标准

- [ ] 规范验收矩阵通过，固定值和已解析引用值结果及错误一致。
- [ ] 旧公式兼容、保存重开、筛选器切换与显式刷新通过。

- [ ] deep-currency-resolution 为独立 Java 工程，可单独构建普通 JAR；公共契约经表格及非表格消费样例验证，规则、单条／批量、并发与依赖检查通过；版本发布及责任明确。
- [ ] 最终协议、包坐标与版本、实际改动锚点及发布限制同步到规范和计划；只实施用户负责的表格接入，不修改他方服务。
