当前事实与影响：

- 表格后端接收已解析的 DF 标签；当前类型只覆盖既有三类公式，新增类型必须同时进入保存、初始查询及引用查询。
- DFFILTER 展示查询前调用 `fetchChildMem`，因此应保留完整选中引用并按格式分支输出，不能全局取消旧转换。
- 成员匹配工具存在父子引用降为子编码的兜底；新属性链路必须严格匹配完整关系。
- 维度服务支持完整父子表达式。`local_currency` 是成员字段，年、版本等属于独立关系激活配置。
- VALUE 标准节点由维度生成，财务模型持有新旧分类规则；PC 三个节点与完整父级合并节点清单不能混为一谈。
- 当前 UD 批量入口按子请求执行，调用方需先合并范围；UD 请求也不能假定已携带成员权限。

## 三、前置条件与协同依赖

- 前后端冻结新增 DF 类型、参数标签、未就绪引用标记及后续批次载荷。前端负责按依赖层提交已解析参数；后端不使用旧单元格值猜测未完成依赖。
- 已配置模型及维度数据源可按名称／别名唯一定位；已有权限上下文的来源和默认权限规则需在接入时核实。
- 测试数据准备两个父级下的同名子成员、空／零／假属性值、不同币种的父子实体、中文及另一语言描述、允许及禁止访问的账号。
- 维度使用 API 开关切换新旧查询链路，涉及权限适配时两边均须验证；本期不实施接口迁移或删除回退链路。
- 新增方法、类型或测试文件均属于待实施设计，不将其名称描述为当前已有代码。优先最小修改，不创建通用公式平台。

## 四、按依赖顺序实施

### 1. 统一公式协议及维度数据源定位

- 修改位置：`deep-table-server` 的 `DFTypeEnum`、`BaseplateFunctionParser.parseValidateDF/parseCellData`、`DataSourceServiceImpl.getCubDataSourceMap/getDataSourceDTO`，以及 `WorkbookManageServiceImplV2` 的初始与引用查询入口。
- 具体改动：新增属性与币种类型；关系格式为可选字段；按对象类型解析模型或维度数据源；新增单项输入／结果映射，并明确未就绪引用沿用后续查询标记。不得把新增公式落入既有金额查询默认分支。
- 依赖关系：先冻结前后端载荷；必要时补维度数据源的元素关联与保存校验。最终 JSON 键名在协议确定后落文档。
- 验证方式：固定值与已解析引用值形成相同求值输入；无效类型、别名歧义、对象类型错误返回公式错误；旧标签和保存结果保持兼容。

### 2. 接入轮次级批量收集与回填

- 修改位置：`WorkbookManageServiceImplV2.mergeCubeExpress/thoroughParseCellData/querySheetBaseplateCellData` 及其引用查询回填链路。
- 具体改动：复用现有 DF 单元格映射，按公式类型分流；以数据源、关系、字段、语言、权限构造结构化分组键及结果键；当前轮次重复项共享结果，单项错误独立回填。初始和引用查询复用同一求值方法。
- 依赖关系：步骤 1；具体求值分支由步骤 3～5 接入。只有职责确实需要时才抽取一个批量求值服务，不把原大型服务拆成无边界的注入服务图。
- 验证方式：重复项只调用对应底层能力一次；不同关系、字段、语言及权限不共享；单项失败不会导致其余合法公式失效；显式刷新重新调用底层。

### 3. 保留筛选器完整实体引用

- 修改位置：`WorkbookManageServiceImplV2.collectNotAroundMem/getDimFilterAroundMem/thoroughParseCellData`，`BaseplateFunctionParser.parseValidateDF`。
- 具体改动：校验可选关系格式并默认 Child；分别保留完整选中引用和旧展示查询成员；只在多版本实体、名称模式、父子格式组合下输出完整引用。描述／别名及多选处理保持原行为。
- 依赖关系：步骤 1；共享能力复用步骤 2，不增加父级搜索。
- 验证方式：覆盖五种显示模式、两种格式、旧公式、非实体维、无父级和重复筛选器引用；检查筛选器依赖记录、切换及刷新。

### 4. 批量读取成员属性并校验权限

- 修改位置：`DimensionBatchService.getUdValueByExpressBatch/queryDimensionMemberV3`、`DimensionApiShowUdServiceImpl` 的值转换，以及新公式对 `DimensionMemberResultUtils` 的使用位置；维度元数据通过既有接口取得。
- 具体改动：按字段元数据校验开放范围；使用完整引用收集成员；合并成员及字段后批查；空值只按 null 处理。不要把未匹配完整关系降级成同名子成员。
- 权限接入：优先调用已有支持权限的成员批查，再仅对允许项读取 UD。普通成员接口若能返回完全一致的值，可在验证动态表一致性后合并查询。若必须补 UD 权限参数，兼容扩展原接口 DTO 及两条处理链，不默认新增 URL。
- 依赖关系：步骤 1～2及数据源权限来源明确；系统字段按已开放情况处理，不扩大开放范围。
- 验证方式：与动态表对照普通／维度关联／值列表属性的返回值；覆盖同名不同父级、无效关系、未开放字段、无权限和 null／0／false；100 个公式按维度及上下文合并，不保留逐公式子请求。

### 5. 抽取模型报表币种解析能力

- 修改位置：财务模型 `CurrencyMappingAdapter/CurrencyMappingV2/CurrencyMapping/NewValueUtil`、`DimensionService.checkAndGetCurrency` 和 `MdxAssistQueryServiceImpl.setMultiEntityParentCurrency` 的相关规则与查询步骤；表格侧增加该能力调用分支。
- 具体改动：独立组织模型元数据及关联实体、VALUE、币种信息，分类 EC、PC、PT 等父级节点与指定币种。预收集所需父／子成员，批查本位币，再按需批查实际币种描述；结果按请求项身份返回。抽取新公式所需规则，避免复制金额聚合及矩阵转换。
- 调用边界：优先财务模型持有币种语义；如必须跨服务新增入口，在财务模型提供纯元数据批量解析，不向维度新增“报表币种”业务接口。最终入口与 DTO 在编码前核对现有接口并冻结。
- 依赖关系：步骤 1～2；沿用模型已有结构，不新增年、期间、场景、版本参数。父级只能来自用户引用。
- 验证方式：执行规范中的 EC／PC／ParentTotal／指定币种示例；缺父级错误、无效 VALUE、描述语言及权限一致；检查调用记录没有金额查询、汇率接口或合并任务。

### 6. 联调保存、刷新与性能记录

- 修改位置：初始底稿、引用单元格查询、保存校验、依赖记录、刷新入口和聚焦测试；以规范验收矩阵为统一依据。
- 具体改动：检查所有入口使用同一规则；保存原始公式及参数；多层依赖由前端按层推进，后端批次输入已解析。记录请求次数、子请求数、内部查询次数、去重数和总耗时。
- 依赖关系：步骤 3～5、前端查询协议与测试数据就绪。
- 验证方式：固定值／引用值结果一致，筛选器切换和保存重开一致；同轮重复共享而新轮刷新读取最新配置；100 个属性公式及重复币种公式完成分组批查。性能绝对耗时阈值按测试环境冻结，不编造毫秒承诺。

## 六、发布、兼容与回退

1. 后端先部署支持旧协议及新公式的版本，前端完成协议联调后才启用新增公式录入与使用；沿用现有发布能力，不默认增加开关体系。
2. 旧 DFFILTER 缺少关系格式保持 Child；新增参数不改变旧字段语义；既有维度接口保持兼容。
3. 已有工作簿不批量重写，新增公式与关系参数随正常保存持久化。发布前保留联调工作簿原始配置及版本备份。
4. 监控新增公式错误率、缺父级／无权限错误、HTTP 和内部查询次数、重算耗时；发现错误先定位受影响公式与分组。
5. 回退前停止新增公式调用和保存，保留含新公式的原始配置；旧后端不保证识别新类型。确需回退的工作簿仅使用事先确认的旧配置备份，不能静默删除新公式或改为本位币标签。
6. 若维度只做了兼容参数扩展，保留旧参数行为，验证开关开启／关闭分支；不删除既有回退链路。

## 七、风险与待冻结事项

| 项目 | 影响 | 应对与责任 |
| --- | --- | --- |
| 新 DF 协议未冻结 | 保存与引用查询可能遗漏参数 | 表格前后端在步骤 1 统一类型、字段、引用状态 |
| UD 权限不能直接透传 | 无权限可能被误判为正常属性值 | 后端复用已有权限成员批查，必要时兼容补参数 |
| 成员结果键只保留子编码 | 不同父级同名成员串值 | 后端按完整关系及返回身份匹配，拒绝子编码兜底 |
| 模型新旧 VALUE 不同 | 错误套用节点模板或币种后缀 | 财务模型后端先定位结构和关联币种，再分类 |
| 属性描述参数未确认 | 可能扩大元数据查询与展示范围 | 首版只返回值，产品另行确认描述能力 |
| 耗时阈值未测量 | 不能据源码估计宣称性能达标 | 后端与测试冻结环境及阈值，保留内部查询记录 |

不存在新增维度 URL或年、版本上下文的默认阻塞项。
