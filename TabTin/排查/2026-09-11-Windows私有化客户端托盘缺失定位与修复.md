# Windows 私有化客户端托盘缺失定位与修复

> 状态：已确认根因并修复源码；重新出包后的 Windows 真机验收待执行
> 最后更新：2026-09-11
> 范围：`private/260907-build-opt` 客户端，不涉及业务服务端

## 现象与结论

Windows 安装及主要功能正常，但托盘没有 TabTin 图标；关闭窗口后任务管理器仍有进程。根因是客户端图标路径与实际打包资源位置不匹配，不是 API、IM 或服务端设置导致。

对比 `private/260907-build-opt`（`9aa6745e32`）与 `release/260909`（`cde13e1fc4`）：托盘创建、图标处理、关闭隐藏策略仅注释有区别。两条线都从主进程模块相对路径读取 `../../static/icon.png`。私有分支没有删除托盘功能。

## 实际安装包对照

| 项目 | 私有化包 | SaaS 包 |
| --- | --- | --- |
| 验证版本 | OP `1.0.1-test.1` | `1.1.9-beta.5` |
| 安装包来源 | 新机任务 `e1d4c890-f3f7-415a-9741-f2977fd0fb20` | `Share/windows/TabTin-beta-1.1.9-beta.5-x64-plain-upload-quick-260909-setup.exe` |
| `app.asar/static/icon.png` | 不存在 | 存在 |
| `resources/static/icon.png` | 存在 | 存在 |
| Electron 读取旧路径 | 空图像 | 非空图像 |
| Electron 读取修复路径并生成托盘图 | 非空图像 | 非空图像 |

标准图标与 preprod 图标在两套包中的 SHA-256 均一致，排除图标内容损坏。标准图标摘要 `16904b954a2429dcdfe79d7553d028052629f68a6c634d2c1c8b9c961d719898`。

两条源码都将图标列入 `build.files` 和 `extraResources`；electron-builder 会将额外资源匹配项用于主应用文件排除，因此不能以 `build.files` 的声明断言 ASAR 必然包含图标。本次 Mac 跨平台私有包与既有 SaaS 包的实际资源布局不同；修复应依赖明确的外部资源位置，不依赖重复打入 ASAR 的偶然结果。

`Tray` 控制器遇到空图像会记录“托盘图标为空，跳过创建”；原关闭窗口判断只检查 `minimizeToTray` 设置，不检查托盘是否已创建，因此仍隐藏窗口并保留后台进程。

## 修复

- 新增 `app-icon-path.ts`：安装包从 `process.resourcesPath/static/` 读取图标；开发态保持基于 `import.meta.url` 的相对路径。普通和 preprod 图标均覆盖。
- `main-app.ts` 接入路径解析器，并把托盘实际可用状态传入关闭/最小化决策。
- `tray-policy.ts` 只在托盘已创建时允许隐藏；否则 Windows 关闭回到已有关闭确认流程，macOS 最小化保持普通系统行为。
- 更新 `assert-main-tray-icon-asset.mjs`：检查 `extraResources` 和真实 PNG，支持 `--resources <解包 resources 目录>`，不再把 `build.files` 当作包内存在的证据。

修改仅涉及上述客户端文件及相关测试，未改动主目录其他任务已有的服务端和部署脚本。
