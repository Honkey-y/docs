## 背景与最新决定

此前已给客户交付过 `private/260907` Community 版本，测试人员通过 AI 临时改地址、手工打包。用户要求规范为网页流程：选客户、填地址、选远程分支和架构，自动拉代码、装依赖、构建、审计安装包并上传共享盘。

用户最初只要求规划和本地验证，随后明确授权直接部署到新 Mac mini。打包机新增目录为 `tools/tabtin-private-pack-gateway/`，开发分支 `codex/private-pack-machine` 从 `release/260905` 创建。客户端源码按网页所选分支固定 SHA，当前已验证 `private/260907`。控制台分支与客户端分支是两件事。

当前同一台 Mac mini 构建 Mac arm64、Mac Intel 和 Windows x64，串行执行；不新增 Windows 打包机。Windows 电脑负责安装验收。保留 Community 原有名称与身份。Mac 默认测试包不公证，正式包复用 SaaS Developer ID 和 Apple 公证；Windows 固定未签名，快速模式跳过源码映射，完整模式仅在本机保存源码映射，两者不代表是否 Authenticode 签名。

服务端部署、数据迁移和 IM 实现由另一位同事负责。本任务只打客户端，API、IM、协作、实时消息、分享页五项地址必须填写。旧 Community 分支的 IM 与 API 共用地址，填不同地址会明确拒绝。未来同源可选 IM/存储和单镜像是另一个工作项。

## SaaS 密钥同步识别与故障原因

之前将 `packers.local` 复制到新机，SaaS 新增人员后副本未同步，所以曾退回统一 token。2026-09-10 已改为每次 API 请求交给 SaaS 实时校验，不再依赖新机映射副本，也不回退旧统一 token。

认证链路：浏览器 → 新机控制台 → `http://127.0.0.1:18787/api/identity/unlock` → 常驻 SSH 隧道 → 旧机 `127.0.0.1:8787/api/identity/unlock` → SaaS 当前人员映射。新机记录 SaaS 返回的姓名：创建任务 `triggeredBy`、上传 `uploadTriggeredBy`、取消 `cancelledBy`。历史“共用令牌（未识别）”不追认个人。

密钥事实源：`/Users/tong/workspace/work/TabTin-pack-gateway-runtime/tools/tabtin-pack-gateway/state/packers.local`，本次核查共 26 人。SaaS 每次验证重读文件，因此新增、改名、撤销在新机下一次请求时生效。为重验，会话暂存在内存中的密钥，最长 8 小时；不写进任务、日志或浏览器持久存储。本文中的本人密钥是用户额外要求的交接记录。

新机 `machine.json` 的 `identityProviderUrl` 当前是 `http://127.0.0.1:18787`。PM2 控制台直连旧机实测 `EHOSTUNREACH`，同机 SSH 终端访问正常；Node fetch 和原生 HTTP 均复现。具体系统限制未进一步归因，不能误诊为密钥失效，也不能说仅是 fetch 库问题。已用 SSH 隧道解决，不要未经验证改回直连地址。

隧道进程 `private-pack-identity-tunnel` 由 PM2 管理，只监听新机回环 18787，转发到 SaaS 回环 8787；SSH 账号为 `tong@192.168.31.236`，专用私钥在新机 `/Users/mini/.ssh/id_ed25519_saas_identity`。旧机只新增受限隧道公钥，未改 SaaS 代码、人员映射或打包任务。SSH 保活断线后由 PM2 重启。身份源不可达返回 503，密钥无效返回 401；已有打包 worker 不依赖身份源持续在线。

## 接手和验收步骤

1. SSH 登录新机，确认三个 PM2 进程在线。`curl http://127.0.0.1:18787/api/identity` 应返回 `required:true`；隧道故障先查 PM2 隧道日志、旧机 SSH 与 8787。
2. 打开新控制台，用 SaaS 个人密钥登录并核对姓名；选客户、分支、版本、架构、方式，交付默认上传。
3. 生成计划，核对 SHA 与五项地址后开始；构建、上传、真机验收分别判断。
4. 更新控制台或重启 PM2 前确认无构建/上传。曾发生 PM2 重启终止构建，不能因 worker 使用 detached 就认为安全。只更新专用控制台 clone。
5. 看 `jobs/<id>/build.log`、`job.json`、审计报告、`delivery.json` 排错。签名、公证、运行时缺失、上传失败分别定位；不要自动 reset/stash 或删除未知源码锁。`machine.json` 必须是标准 JSON，曾因尾部误写字面量反斜杠 n 导致启动失败，保存后先解析检查。

用户要求暂停此前定时任务，未恢复自动监控。身份 SSH 隧道属于常驻控制台依赖，不是定时打包或提醒。三个进程已 PM2 save，并加载现有登录启动项 `~/Library/LaunchAgents/pm2.mini.plist`（`gui/501/com.PM2`）；尚未模拟整机重启，不能把当前在线等同于断电恢复验收。真实停止隧道时身份请求返回不可达错误，重新启动隧道后本人密钥恢复 200 / 杨凯胜。
