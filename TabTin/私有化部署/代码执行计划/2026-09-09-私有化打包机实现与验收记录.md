## 已实现的用户路径

1. 选择本地执行机，或在机器配置中接入第二台 Mac/Windows 执行端。
2. 新建/保存客户配置；API、IM、协作、实时消息、分享页五项地址必填。IM 可与 API 相同，但不能留空后静默推导。
3. 填写源码 ref、明确版本、平台架构及“只生成本地包 / 打包后上传”。
4. 生成不可变计划，查看实际源码 SHA、五项地址、配置摘要、本地目录和共享盘目标。
5. 预检就绪后提交任务，查看队列、构建阶段、日志和下载；预检或构建失败不会产生虚构安装包。
6. 上传只进入 Share/private；失败保留本地制品，可重试上传。

本地输出保持原约定：Mac `apps/tabtin-electron/dist-app-quick/`，Windows `apps/tabtin-electron/dist-app/`。共享盘分别为 `/Volumes/Share/private/` 与 `C:\Share\private\windows\`。本轮只在临时夹具验证复制与失败行为，没有挂载或写入真实共享盘。

## 实现与取舍

- 新目录只依赖 Node 标准库，没有引入新的 Web 框架或控制台运行依赖。
- 没有调用旧 SaaS Runner 的自动 stash、版本取号、服务端部署或更新发布流程。只复用 Electron 完整构建/签名/公证及原有产物审计。
- 私有计划通过显式文件传入；Vite 在读取原 profile 后应用已校验的客户值。没有修改开发目录 `.env.production` 或在工作源码中临时改 `package.json`。
- 在临时 deploy 包中写入客户身份与配置摘要；客户数据根、运行时根、默认工作目录和注册协议分别隔离。Windows 使用客户专属主程序名，并同步签名钩子的精确匹配、验签路径与 NSIS 卸载清理；避免停止 SaaS 同名进程或清理其凭据。
- 私有客户端禁用自动更新入口和 Sentry；旧错误上报器在发出请求前受私有开关约束。源码映射只保存到任务证据目录。
- 原 SaaS 无私有计划参数时保留原行为。没有迁移 `private/260907` 的客户端 Django 聊天实现；IM 地址配置不等于切换聊天实现。
- Windows 的 app.asar 审计在共享脚本删除临时输出前执行，适配器读取本次审计报告，不误读历史 `win-unpacked`。
- 每个状态目录有控制台进程锁，每个源码目录有构建锁；独立 worker 保留状态。控制台重启后核对 PID，死亡构建标为中断，死亡上传标为失败，不自动重打不确定任务。
- CLI 执行任务通过已启动控制台提交，避免两个调度器争写队列。它不自动 checkout/pull；专用构建 clone 需提前检出拟打包 SHA。开发 linked worktree 不可标为构建根。
- 本版按单目标任务交付；远程执行机分别保存配置与历史。跨机器自动汇总交付、多个架构一键汇总尚未实现，操作人员需在不同执行机使用相同客户配置、版本和 SHA。
