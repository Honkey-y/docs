普通整机 Compose 的 15 个服务：PostgreSQL（pgvector/PG16）、Redis、Django、8 个不同队列的 Celery worker、Celery beat、Centrifugo、collab-live、Caddy。

当前连接关系：

```text
桌面客户端
  ├─ API → Caddy :8080 → Django → PostgreSQL / Redis
  │                                ↕
  │                           Celery workers + beat
  ├─ 实时事件 → Centrifugo :8100
  └─ 文档/表格协作 → collab-live :4100 → Django / Redis

当前聊天所需、尚未并入上述 Compose：
桌面腾讯 Provider → Go IM control ↔ 腾讯云 IM
                       ↕
                 PostgreSQL / Django
```

服务端容器化不包含桌面客户端。用户仍需安装并连接到对应企业服务地址。公开分享 Web 也不等于完整桌面应用的浏览器替代品。

## 已有能力与交付缺口

### 1. 首次安装与初始化

已经具备：Django/协作服务 Dockerfile、非 root 运行用户、健康检查、容器重启策略、PG/Redis 独立卷。Django web 入口执行 `safe_migrate`，worker 等待 Django 健康后启动。

[`bootstrap_fresh_db.py`](/Users/yang/Documents/larchiveai/TabTin/apps/tabtin_django/apps/maintenance/management/commands/bootstrap_fresh_db.py) 提供幂等的会员配额、模型场景和计费定价初始化；默认显式执行，可通过 `RUN_BOOTSTRAP` 选择启动时执行。

仍需打通：首次管理员创建及登录、Organization 初始化、模型凭据及路由、组织余额/配额政策。基线 seed 不包含模型真密钥，也不代表 Agent 已可使用。`bootstrap_admin_accounts` 是为已有 staff 用户补后台账号和角色，并非全新的首任管理员安装向导。

[`docker-entrypoint.sh`](/Users/yang/Documents/larchiveai/TabTin/apps/tabtin_django/docker-entrypoint.sh) 对自动 bootstrap 失败只打印告警并继续起服务，因此“容器健康”不能证明初始化完成。

### 2. 配置模板与首启存在可复现问题

- Compose 已固定 `DEBUG=False`；[`compose.env.example`](/Users/yang/Documents/larchiveai/TabTin/deployment/compose.env.example) 却仍声称默认 DEBUG=True、无需密钥可启动。`settings.py` 对 SECRET_KEY、独立 JWT/凭据密钥、实时层密钥等有生产启动校验，另有 DAEMON_TOKEN_SECRET、SOURCEMAP_UPLOAD_KEY 检查。后两项即使本次不交付 Daemon，也属于当前后端启动约束，需纳入配置清单评估。
- Compose 的 `CENTRIFUGO_*: ${CENTRIFUGO_*:-}` 使用编排阶段插值；服务级 `env_file` 不提供该插值输入。只填 `deployment/compose.env` 会被 `environment` 中的空值覆盖。隔离副本实测可复现；显式 `--env-file` 可解决这几个字段的插值，但不是全部首启问题的修复。
- PG 账号密码在 Compose 中写死。隔离副本实测，即使显式传 `--env-file`，仍不能覆盖该密码。已有数据库卷的密码轮换还需真实修改数据库账号，不能只改文本。
- collab-live 仍设 `NODE_ENV=development`，未注入 `LIVE_SECRET`；Django 默认协作共享密钥也是开发值。客户配置要显式对齐两侧强密钥和运行环境。
- 普通 Caddy 配置关闭自动 HTTPS，宿主暴露 8080、8100、4100。交付前需要确定客户域名、TLS、代理路径与允许的访问入口。

### 3. 云依赖决定“私有化”的实际范围

| 能力 | 当前事实 | 对客户的含义 |
| --- | --- | --- |
| 聊天 | 腾讯 Provider + Go IM；正文、实时投递、热历史等由腾讯云 IM 承载 | 当前不能承诺聊天数据全部留在客户内网；Go 服务部署在客户侧也不改变这个事实 |
| 文件/附件 | Compose 设计复用阿里云 OSS；服务工厂支持 `aliyun`、`local` | local 明确标为开发用途，不能直接承诺生产级内网存储；当前工厂未提供直接可选的 S3/MinIO provider |
| AI | 基线模型、场景和计费初始化已具备，仍需凭据/路由/配额 | 客户自有模型接入要按真实对话、工具调用、向量化等分别验收，不能只填一个地址即宣称完整支持 |
| 短信、邮件、语音、搜索、支付、推送 | 分散的外部服务配置 | 应逐项确定启用/关闭、凭据归属、联网要求和不可用时的产品行为 |
| 构建与更新 | Dockerfile 默认使用 TabTin ACR 基础镜像及语法前端，并访问包源；更新存储走 OSS | 应提供客户可获取的版本化镜像/制品；离线安装包、私有更新源和无公网构建均未在本次证实 |

存储证据：[`factory.py`](/Users/yang/Documents/larchiveai/TabTin/apps/tabtin_django/apps/services/oss/services/factory.py)；`local` 更新存储被显式拒绝，不能将本地附件存储与客户端更新交付混为一谈。

### 4. 客户端接入已经有基础，但仍需完整验收

[`DebugEnvironmentDialog.tsx`](/Users/yang/Documents/larchiveai/TabTin/apps/tabtin-electron/src/renderer/src/components/debug/DebugEnvironmentDialog.tsx) 支持输入自定义基础地址、显示端点并应用重启；功能受构建开关控制。不能假定每一个已发安装包都开放该入口。

[`debug-environment.ts`](/Users/yang/Documents/larchiveai/TabTin/apps/tabtin-electron/src/shared/debug-environment.ts) 会派生 API、任务 WS、公开 Web、Centrifugo 和协作地址；其协作基础地址与普通 Caddy `/collab/*` 规则是否匹配，需要沿实际协作 URL 构造做端到端验收。该配置对象未包含独立 IM 端点，当前 IM 的实际环境归属也需另查。已有切换入口不等于客户端所有出站连接已转为企业环境。

### 5. 可维护性交付尚未形成统一闭环

PG/Redis 持久卷已具备，旧单库验收也有实际通过记录。但本次没有找到与当前整机配置配套、覆盖数据库与附件及密钥的客户备份恢复闭环，也没有证明当前版本升级/回滚演练通过。

现有部署脚本以拉代码、构建、启动、检查健康接口为主。建议交付物补齐：固定版本/镜像摘要、版本兼容清单、迁移顺序、升级前备份、失败恢复、数据恢复演练、日志采集和容量基线。镜像回退与数据库恢复是两件事；有迁移时必须分别定义。

不在本轮给最低硬件承诺：8 个 worker 的并发与多种文档/媒体任务使内存需求随工作负载变化，需要在约定用量下量测。

## 建议接手顺序与验收路径

第一步先约定客户承诺：允许哪些云服务、哪些数据可出客户网络、交付哪些终端、谁负责升级与日常运维。优先考虑“企业自有服务器部署核心服务，允许明确列出的云依赖”。完全离线版另立范围，尤其不能将当前聊天架构简单更换 Compose 参数就称为离线版。

第一轮交付建议只聚焦一个可重复的 Linux 单机方案：

1. **部署清单收敛**：以现有 Compose 为底座，补齐 Go IM、管理后台和需要的公开 Web，明确迁移与网关路由；不恢复 Django IM 遗留链路。
2. **从空白服务器到可登录**：先预检域名、端口、镜像访问和配置，生成并保存独立密钥，初始化管理员/组织/模型与配额。任何关键初始化失败都应在交付验收中失败。
3. **真实用户闭环**：安装约定客户端 → 连接企业环境 → 管理员及普通成员分别登录 → 建表写记录 → 两个用户共同编辑文档 → 上传下载附件 → 聊天及 @Agent 回复 → 外部分享（如交付范围包含）。每步同时留用户界面、服务日志和数据断言证据。
4. **持久化与恢复**：重启全部服务后数据仍可读；备份业务库、IM schema/库、附件和必要配置/加密密钥，在另一套空白环境恢复后重复用户验收。腾讯云消息历史的保留与恢复责任须单独说明。
5. **升级与失败路径**：旧客户端连接新后端，已有记录/附件/聊天仍可用；验证错误密钥、模型无额度、云服务不可达、升级中断时能明确定位，并按既定恢复方案处理。

这项工作的价值在于让客户“装得上、用得起来、数据能恢复、后续敢升级”。容器编排只是其中一个交付物。
