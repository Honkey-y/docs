# 核心概念

> 状态：草稿
> 最后更新：2026-09-08
> 适用范围：TabTin 产品名词及代码阅读
> 关联文档：[入门目录](说明.md) · [上一篇](01-产品是怎么用的.md) · [下一篇：架构地图](03-用后端经验看架构.md)

先用一句话串起来：**你在一个组织里，和同事围绕某个项目协作，让自己的 Agent 完成任务；需要读写本机文件时，在自己的工作空间里执行。**

下面的“新人上手”都是示例名称。

## 常见名词分别回答什么

| 概念 | 它回答的问题 | 放进例子里 |
| --- | --- | --- |
| 组织（Organization） | 成员、权限和资源归哪个组织管理？ | 公司在 TabTin 里的组织 |
| 项目（Project） | 大家围绕哪件事协作？ | “新人上手”项目，共享资料和进度 |
| 用户（User） | 哪个真人在参与？ | 你、带教同事 |
| 智能体（Agent） | 哪个 AI 身份在帮忙？ | 你配置的助手，带着自己的规则和技能 |
| 工作空间（Workspace） | 本地任务在哪个现场执行？ | 你的电脑上，用于本次工作的一个目录及其规则 |
| 设备（Device） | 实际由哪台机器提供执行能力？ | 你的电脑 |
| 应用（App） | 用什么工具处理成果？ | 用 TabDoc 编辑“学习清单” |

组织管整体权限和资源边界；用户持有自己的 Agent 和设备。把 Agent 加入项目，是增加一个协作参与者。

## 最重要的区别：项目和工作空间

你和同事都参与“新人上手”项目，但你们各自在自己的电脑上干活。

- **项目共享的是协作内容**：目标、成员、事项、任务，以及可见的文档和文件引用。
- **工作空间提供的是个人执行现场**：某台设备上的一个执行目录，以及目录规则和信任状态。
- 加入同一个项目，不会自动开放彼此的本地目录。需要共享成果时，要通过资源共享或交接来完成。

一个工作空间对应单一执行根目录。项目和 Agent 都不拥有工作空间；任务需要本地能力时，绑定执行者可控的工作空间。

## 事项、任务、运行：从大到小看

| 概念 | 用途 | 例子 |
| --- | --- | --- |
| 事项 | 看板上的进度卡片 | “完成新人学习清单” |
| 任务 | 围绕目标持续工作的记录，可以继续对话 | “帮我整理资料”的那条任务 |
| 一次运行（TaskRun） | Agent 某一次具体执行 | 整理第一版；之后再执行一次补充内容 |

一个事项可以关联多条任务；一条 Agent 任务可以发生多次运行。

**Agent 跑完一次，不会自动代表事项完成。** 你还要检查成果，再按团队的方式更新事项进度。

## Agent、模型、技能也要分开

- **模型**：理解语言、生成回答和提出下一步行动的能力来源。
- **Agent**：带有身份、规则、技能和模型偏好的 AI 参与者。
- **技能（Skill）**：教 Agent 按某种方法办事的说明和配套资源。

例如：“助手按照团队的文档整理技能，调用某个模型，整理学习清单。”三者在其中承担不同角色。

## 看到旧代码名怎么办

`Session` / `Conversation` 常用于任务或会话的实现名；`Task` 在某些模块里指事项。遇到 `Space` 这类历史名称时，要看具体模型和调用处，不按英文直接推断。

截至本次核对，后端已经有独立的 `Project`、`ProjectMembership` 模型。旧资料里“Project 就是某种 Space”的实现说明已经不能直接照搬。
