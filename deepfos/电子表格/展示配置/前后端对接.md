# 对齐方式与表头自动换行对接

> 状态为评审中，更新于 2026-11-06。
> 适用于 DeepTable 后端分支 `codex/table-display-settings`。
> 关联文档为[后端实施清单](代码执行计划/2026-11-06-对齐与表头换行后端清单.md)和[接口验证记录](验证记录/2026-11-06-本地接口回归.md)。

接口路径省略服务前缀，示例仅列本次涉及的字段。

## 保存入参

沿用 `POST /workbook/save-info`、`POST /workbook/save-info-zip` 和 `POST /workbook/check-info`。压缩接口在 gzip 压缩前的 JSON 中添加字段。

| 场景 | 新增字段位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| 动态表 | `districtScriptArrayStr` 中对应区域的 `alignment` | string | 区域级对齐，脚本增加一行 `alignment=center` |
| 数据表来源浮动行表 | `floatingTableInfoList[].columnList[].alignment` | string | 每列独立配置 |
| 对象／模型来源浮动行表 | `floatingTableInfoList[].dsInfo.activeFields[].formValues.alignment`、`floatingTableInfoList[].dsInfo.rowFields[].formValues.alignment` | string | 在对应列的 `formValues` 中添加 |
| 浮动行表全部来源 | `floatingTableInfoList[].headerAutoWrap` | boolean | 区域级表头自动换行，与 `hideTitle` 同级，默认 `false` |

`alignment` 取值如下。

| 值 | 含义 |
| --- | --- |
| `default` | 按单元格实际类型采用原有对齐规则 |
| `left` | 左对齐 |
| `center` | 居中 |
| `right` | 右对齐 |

```json
{
  "districtScriptArrayStr": "sheet_id=SHT001\ndistrict_id=DIT001\nalignment=center\n",
  "floatingTableInfoList": [
    {
      "districtId": "FLOAT001",
      "hideTitle": false,
      "headerAutoWrap": true,
      "columnList": [
        { "id": "dateColumn", "alignment": "center" },
        { "id": "amountColumn", "alignment": "right" }
      ]
    }
  ]
}
```

前端在现有完整区域脚本、区域对象和列对象中补充这些字段，并沿用现有增量保存逻辑。

## 返回字段

| 接口 | 返回位置 |
| --- | --- |
| `GET /workbook/find-info` | `data.sheetInfoList[].districtInfoList[].alignment`，以及 `data.sheetInfoList[].floatingTableInfoList[]` 下上述列级 `alignment` 和区域级 `headerAutoWrap` |
| `POST /workbook/data-query-V2` | `data.sheetList[].districtInfoList[].alignment`，以及 `data.sheetList[].floatingTableInfoList[]` 下上述列级 `alignment` 和区域级 `headerAutoWrap`，包括分页查询 |

## 默认与透传规则

- 后端按原值保存和回传 `alignment`。历史缺失时可能返回 `null`，前端将缺失、`null`、空字符串和未知值均按 `default` 处理。
- 默认时文本、日期及维度显示值左对齐，数字、比率右对齐，前端按实际类型判断。
- `headerAutoWrap` 历史缺失时返回 `false`。`hideTitle=true` 时前端置灰换行选项，并保留其值一起保存。
- 多维浮动行表的逐列对齐沿用顶层 `districtExt` JSON 字符串。每个区域的逐列配置再以 JSON 字符串值存入扩展位，后端保存回传。扩展键名、列标识由前端约定，并补齐序列化、回读及预览应用逻辑。
