## 环境与方法

- 分支为 `codex/table-display-settings`，独立运行 `boot-parent/deep-table-boot/target/deep-table-server.jar`，使用单一 Spring 配置 `test`。
- 本地地址为 `http://127.0.0.1:18088`，进程号为 `94741`，验证结束时健康检查返回 `UP`。
- 仓库 `application-test.yml` 的外部地址当前为 alpha-pg。本次通过启动参数将 `api.tempHttpUri`、`server.name.space`、`server.name.system` 覆盖到 `https://test.deepfos.com/deepfos-server` 下相应服务。
- 使用 Playwright MCP 打开用户提供的 `float_smart_list_02` 和 `table_df_01_copy`，分别抓取编辑态及切换使用态后的实际请求，再保留会话头和请求体，以 curl 重放至本地地址。
- 保存验证使用两个临时工作簿副本，复制原始元素内容后，通过本地保存接口修改新增字段。副本已删除，并通过元素查询确认清理完成。

## 抓取与重放的接口

| 场景 | 请求 |
| --- | --- |
| 编辑态 | `GET /workbook/find-info` |
| 使用态预查询 | `GET /workbook/data-query-pre` |
| 筛选器 | `POST /workbook/query-filter-v2` |
| 底板 | `POST /workbook/query-sheet-baseplate-V2` |
| 首次加载、查询与分页 | `POST /workbook/data-query-V2` |
| 配置保存 | `POST /workbook/save-info-zip`，gzip 请求体 |

两张报表共 10 个初始读取、查询请求重放成功，均返回 HTTP 200、`status=true`、`code=0`。另抓取浮动行表第 2 页的查询请求用于分页验证。浮动表保存同时覆盖普通 JSON 入口 `/workbook/save-info` 和页面使用的压缩入口。

## 实测边界与过程记录

- 本轮实测覆盖用户提供的数据表来源浮动行表和动态表。对象／模型来源的新增配置已有自动化序列化覆盖，实际对象／模型表单需要对应测试报表继续联调。
- 页面当前版本尚未接入新增控件和展示逻辑，本轮验证对象为后端请求解析、实际持久化、编辑态回读、使用态响应和分页契约。视觉对齐、换行行高及 Excel 输出需要前端接入后验收。
- 首次抓取动态表保存时，页面调用压缩入口，最初对普通保存入口的拦截未命中，因此对原动态表触发了一次现有配置保存，接口返回成功，当时尚未加入测试字段。最终再次读取原动态表，完整 `find-info` 数据与最初读取结果比较一致。
- 最后回查原动态表时曾遇到一次外部维度服务 HTTP 404，重试恢复成功，随后完成原报表配置比较与副本清理。

## 本地复现资料

- 请求、响应、启动日志及可执行 curl 脚本保存在 `/tmp/deeptable-display-verification/`。
- `baseline-results.jsonl` 记录初始请求重放结果，`float-feature-results.log`、`dynamic-feature-results.log` 记录保存回读断言，`clone-query-results.log` 记录使用态配置位置。
- 每次请求对应同名 `.curl.sh` 和 `.response`，curl 从该目录的 `headers.curl` 读取本次浏览器会话头。临时副本的保存与查询脚本依赖已经清理的副本身份，再执行前需重新创建测试副本。
