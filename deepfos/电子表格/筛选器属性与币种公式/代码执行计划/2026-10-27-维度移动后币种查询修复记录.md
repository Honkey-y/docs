# 维度移动后币种查询修复记录

> 状态：已确认
> 最后更新：2026-10-27
> 适用范围：DeepTable 的 DFCurrency 元数据查询
> 关联文档：[功能与后端规范](../规划/功能与后端规范.md)、[主题说明](../说明.md)

## 问题与依据

工作簿 `DF_formula_regression_20261026` 的 `Consol` 是模型 `Main_Cube` 的别名。模型主内容的维度列表仍保留旧目录，而当前关联内容已指向移动后的目录。DFCurrency 调用 `justFindCube` 后直接使用主内容中的 Entity／Value 身份，因此向旧目录查询。旧目录查询报错，新目录查询成功；同一实体的 DFUD 可返回 CNY。

## 修复范围

- 在 `MetadataFormulaService` 中按维度的 `dimensionRelKey` 读取当前 `relationObj`，采用当前名称、目录、路径、服务。
- 关联缺少服务名时根据当前身份解析所属服务，不沿用主内容中的历史服务。
- 没有登记关联键的旧模型保留原字段兼容；有键但关联缺失或不完整时明确报错，不回退历史身份。
- 关联只有路径时使用路径定位，实体与 VALUE 的关联匹配也遵循此规则。
- 不修改 `justFindCube` 通用语义，不改写共享模型对象，不查询数据表、金额或汇率，不改前端和币种解析库。

## 验证

新增 4 项测试在修复前均失败，修复后 DeepTable 全模块 123 项通过。覆盖新旧维度名称／目录／服务冲突、模型快照不被修改、关联缺失／不完整、所属服务重新解析和仅按路径定位。原有 EC、PC、父级合并节点、指定币种及权限失败用例继续通过。

独立 DeepTable Boot 与统一 Boot 均打包成功。本地仍使用独立 DeepTableBootApplication、test profile、8089 端口，前端 3002。

真实 HTTP 重新发送原失败请求后，EC 与 PC 返回 CNY；父级合并口径的 description 返回“中国人民币”；同一实体 DFUD 返回 CNY。缺父级及不存在的完整关系继续返回错误。重启后查询日志不再出现旧维度目录 ID。

浏览器刷新本地回归表，B5 由 #VALUE! 恢复为“中国人民币”。表内保留有意设置的负例，其预期错误没有被隐藏。上述验证当时未保存远端工作簿。该修复后续已提交为后端 7f4ed63，合入 test 并推送；推送不等于已完成测试环境部署验证。
