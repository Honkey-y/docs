## 二、实际实现落点

用户追加确认完成作业也采用年度分表，覆盖原方案中作业使用普通历史表的决定。新增 `JobHistoryTable` 与 `JobHistoryTables` 统一路由和预建，主表为 job_history_YYYY，明细为 job_content_history_YYYY。主体以 endTime 按 spring.jackson.time-zone 归年，明细跟随主体。启动及每日预建本年／次年，首次归档历史年份通过独立 DDL 边界准备该年。

年度 DDL 对齐 ES 业务实体的 24 个主体属性与 13 个明细属性，包含来源 IP、回调、三语言、计数及全部时间。新增物理明细 id 列保存原实体 getId 的计算值，保留 500 字明细 key 和毫秒日期精度。tenant_scope 是继续保留的内部企业隔离列。

作业按原日期、空间、应用、用户及状态筛选，条件下推各年度分支后由数据库统一排序分页，精确 COUNT 在年度内计算后求和。已有普通历史主明细仍可读取、定位和删除，新归档写年度表。创建即完成的跨年重复 ID 通过活动主表 ID 事务锁串行化，归档入口和 DB save 使用 READ_COMMITTED 保证最新提交可见。首次历史年 DDL 在挂起业务事务的独立边界执行，归档失败可整体回滚活动数据和历史主明细。


本轮按用户确认改为存储策略。两个模块的 OperationLogStore 分别复用各自 ESLogServiceImpl／DbLogServiceImpl，作业历史 JobHistoryStore 复用 ESJobServiceImpl／DbJobHistoryServiceImpl，Spring 按 platform.search.mode 唯一装配。原业务服务注入策略接口，完成权限、明细合并、事务、回调及导出。ES 索引检查和仓库调用集中在 ES 实现中，DB 年表及历史表调用集中在 DB 实现中。

保留旧 ES 多 ID 接口固定返回 null 的兼容判断，实际读取已统一经 JobHistoryStore。完成作业越界空页在保留 total 后直接返回，避免对空结果请求用户补全。

## 四、本地自动验证

2026-11-05，JDK 21、Maven 3.9.11，执行：

```shell
mvn -pl system-server -am clean test -DskipTests=false \
  -Dtest=LogYearRangeTest,SearchDdlTest,SearchMapperTest,SearchInitializationTest,SearchModeContextTest,StoreStrategySelectionTest,DatabaseSearchIntegrationTest,SearchTableMetadataTest,EnterpriseLogAuditorTest,JobServiceImplBatchRemoveTest \
  -Dsurefire.failIfNoSpecifiedTests=false
```

本轮结果：23 个 Reactor 模块编译通过，共运行 **90 个用例，86 个通过、4 个失败**。策略唯一装配、ES 启动、22 个删除权限、8 个企业日志审计及归档回滚用例通过。本轮新增验证跨年分页与计数、旧普通表兼容、全 ES 属性往返、跨年同 ID 并发归档、独立 DDL 的回滚边界和跨年持续运行预建。`git diff --check` 通过。

4 个失败用例分别是原 SQL 初始化标记过滤、异常表堆栈字段扩容及两项完整异常堆栈读写。当前 SPACE-INIT／SYSTEM-INIT 缺少对应标记，用户已确认正在独立调整 SQL 脚本。本轮保留当前脚本正文，这 4 项待 SQL 调整后恢复验收。

本轮另验证 common 语句重复 ID 明确失败、实体化的空间／应用／模块／用户修复范围及空值行为。

新增逐方言测试直接对照原 LogMapper.insertLog 的字段集合与年度 DDL，验证年表没有增删操作日志字段；另核对关键字段长度。异常表初始化测试验证 ES／DB 仅原堆栈列容量不同、其他 SQL 与字段保持原样。

内存集成用例使用仅 test scope 的 H2，不增加运行依赖、不连接客户数据库。它验证 SQL 执行、事务和映射，不等价于 PostgreSQL 或六类数据库的实库通过。
