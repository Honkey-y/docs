# 菜单权限跨环境迁移

> 状态：已确认
> 最后更新：2026-10-15
> 适用范围：DeepFos 菜单元素自定义用户、用户组授权的跨环境导入导出
> 关联文档：[菜单权限跨环境迁移修复计划](./代码执行计划/2026-10-15-菜单权限跨环境迁移修复计划.md)

## 问题与目标

菜单项的自定义授权直接保存用户 ID 和用户组 ID。A 环境的菜单导入 B 后，身份编码相同但 ID 不同时，原授权不能自动对应到 B 的用户、用户组；编辑配置时可能回显为无用户、用户组。

本次方案是在菜单后端保存时附带用户名、用户组编码，复用现有元素导入后置通知，在目标环境解析并替换 ID。导出沿用现有元素导出流程。

## 已确认规则

1. 运行时继续按 `userIds / groupIds` 鉴权。
2. 菜单后端保存时补齐 `userIdsByName / groupIdsByCode`，以用户名、用户组编码为 key，以当前 ID 为 value；不新增导出前置或后置接口。
3. 新增菜单 `ELEMENT_IMPORT / REAR` 处理接口；通知配置同步进入组件声明，并在初始化脚本中补充 `sys_melement_operate_notice_config` 记录。
4. 每个身份只在目标环境唯一匹配时替换 ID；未匹配、匹配多条均保留该项原 ID，不清空，不任意取第一条。
5. 原 ID 在 B 查不到时，沿用现有配置页显示无用户、用户组的行为，作为提示；本次不新增错误字段或提示 UI。
6. 按用户最后更正，用户和用户组均按目标空间候选匹配；企业内存在但未加入目标空间的用户、其他空间同编码组都不参与候选，未匹配时不回退到企业级查找。
7. 用户沿用 `SpaceApi#batchQueryUserByNames` 协议，并将内部空间成员查询优化为仅校验本次候选 ID、使用 Set 过滤；用户组新增按空间和组编码批量精确查询的薄接口，复用已有 SQL。不采用全空间用户或组列表，空候选不触发全量查询。现有组 `by-name` 接口按组名称查询，不能用于组编码匹配。

单层 `groupIdsByCode` 适用于菜单引用所属空间用户组的场景。实施前需核查现有授权是否允许跨空间引用；若同一菜单引用多个空间的同编码组，需要补充空间映射设计，不能直接合并成一个编码 key。
