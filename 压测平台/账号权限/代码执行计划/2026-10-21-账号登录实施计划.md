## 一、目标与当前依据

交付注册登录、内置管理员、首次强制改密、失败锁定、Redis 会话及统一身份识别，不包含团队授权页面、SSO 或找回密码邮件。依赖可用 MySQL、Redis 和独立测试数据目录；安全参数的管理展示由权限计划接续。

当前 `backend/pom.xml` 仅有 `core、app`；`InfrastructureConfig` 已配置 Redis 客户端；`SchemaUpgradeRunner.upgrade` 只扫描 `db/core`；`frontend/src/api/client.ts` 自动把非全局接口放入当前项目路径。既有异常格式位于 `app/exception/ApiErrors.java`；`SettingsServiceImpl` 已有类别定义、取值及版本校验，可提取通用契约复用，不能让账号模块反向依赖 `app`。

## 二、实施步骤

1. **建立可选装配**：在 `backend/pom.xml、backend/app/pom.xml` 规划账号可选构建及拟新增 `backend/account/`。将能力、请求上下文、设置类别注册及读写等必要通用契约提取至拟新增 `backend/access/`，由 `app、account` 分别依赖；设置持久化仍由既有 `SettingsMapper.xml` 实现，扩展只注册账号安全类别。在 `SchemaUpgradeRunner` 为扩展配置独立脚本与记录，前端构建选择扩展入口。验证排除账号源码后仍能构建、启动且不查账号表或安全类别。
2. **实现账号与管理员初始化**：账号模块按 MVC、Service 接口／实现、DTO／PO／VO 和 MyBatis XML 分层，增加账号类型、状态、强制改密标记。启动初始化在建表后、开放请求前按规范幂等创建 `admin / admin`，只存摘要和完成标记；普通注册保留名冲突拒绝。验证首次插入、并发启动唯一性、重启不覆盖已改密码，以及初始化后管理员丢失不自动重建弱密码。
3. **实现登录与强制改密**：拟新增 `/api/v1/auth/register、login、logout、password` 及 `/api/v1/me`，前四项为 POST，当前用户为 GET。登录返回 `{token, expiresAt, passwordChangeRequired}`；待改密账号仅有本人资料、改密、退出和公共启动信息权限，修改路由或直接调业务接口也拒绝。改密须校验旧密码，成功后删全部 Token 并重新登录。验证默认 admin 及管理员创建／重置的普通账号均不能跳过此流程。
4. **实现 Redis 会话与锁定**：新增会话 Service 和 `OncePerRequestFilter`，Cookie 名使用 `deep_jmeter_token`，Redis 会话键及用户 Token 索引按规范原子维护。登录最终校验／签发与改密／重置／停用使用同一账号行锁串行；清理失败回滚账号修改，退出只删当前 Token。安全参数从注册类别读取；失败计数和临时锁定原子更新，返回 423 及剩余秒数，来源限流另返 429。验证多设备撤销、计数边界、锁定到期、策略更新和并发登录／重置。
5. **建立上下文与错误边界**：过滤器识别账号类型和强制改密状态，填充不可变 `RequestContext`，请求结束 `finally remove()`；超级管理员业务禁入及团队项目授权由下一计划补齐。精确注册公共 `/api/v1/access`，业务未映射时默认拒绝，过滤器统一写错误与追踪标识。验证无效 Token 401、缓存故障 503、线程复用无身份残留，均不转匿名放行。
6. **接入登录界面与 Cookie**：修改 `App.tsx、api/client.ts` 和拟新增账号页面，复用现有紧凑表单与状态样式；auth、me、access、teams、admin、invitations 等全局入口不加项目前缀。前端统一写／清 `deep_jmeter_token`，补齐写请求防护头及批量下载独立 fetch；统一错误对象保留 `code、retryAfterSeconds`，配合后端错误体及 `Retry-After` 显示锁定倒计时。待改密固定进改密页，普通用户进团队入口，超级管理员进人员入口；401 提示重登并保留草稿，503 展示故障。验证根路径及 `/jmeter/` 子路径。

## 三、验证与完成标准

- [ ] 登录、注册、改密与当前工作台对照截图中的字体、配色、控件和间距一致，桌面／窄屏无溢出；错误、加载、焦点和禁用态符合统一规范。
- [ ] 默认管理员首次改密前不能进入人员、设置或项目业务；改密后重启不恢复默认密码，普通创建／导入账号不能取得超级管理员类型。
- [ ] Redis 会话及用户索引一致：当前退出只影响本会话，改密／重置／停用删除全部设备 Token；并发旧密码登录不能遗留有效 Token，清理故障不报修改成功。
- [ ] 失败阈值、窗口边界、正确密码不能绕过锁定、到期／人工解锁、参数更新及超级管理员同样受锁均通过；启用账号不恢复已删除 Token。
- [ ] Cookie 属性、可信 Origin、自定义头、注册／登录限流通过真实浏览器验证；JSON、multipart、批量下载请求均覆盖。
- [ ] 请求复用线程和两账号并发不串身份，认证失败不进入业务方法，日志不记录密码、原始 Token 或邀请随机码。
- [ ] 无账号构建不请求用户接口、不跳登录、不需要会话缓存；已有压测与导出仍可用。账号模式此阶段尚未完整开放业务，依赖下一计划完成授权。

按入口文档执行构建、格式与相应测试后本地提交；本阶段只在隔离测试环境启用。回退恢复匹配程序和数据备份，不通过关认证掩盖故障。前端可写 Cookie 带来的脚本读取风险须与游客计划中的原生报告隔离一起关闭，不能仅以登录成功作为整轮交付完成。
