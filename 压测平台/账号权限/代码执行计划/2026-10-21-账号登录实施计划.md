# 账号登录实施计划

> 状态：草稿，未执行
> 最后更新：2026-10-21
> 适用范围：本地账号与 Redis 会话
> 关联文档：[统一规范](../规划/账号与团队项目规范.md)、[共同交付要求](../说明.md)

## 一、目标与当前依据

交付注册、登录、退出、改密和统一身份识别，不包含团队授权页面、SSO 或找回密码邮件。依赖可用 MySQL、Redis 和独立测试数据目录；实现前锁定规范中的建议参数。

当前 `backend/pom.xml` 仅有 `core、app`；`InfrastructureConfig` 已配置 Redis 客户端；`SchemaUpgradeRunner.upgrade` 只扫描 `db/core`；`frontend/src/api/client.ts` 自动把非全局接口放入当前项目路径，不能直接用于未来登录接口。既有异常格式位于 `app/exception/ApiErrors.java`，过滤器异常不能假定由 Controller 异常处理器捕获。

## 二、实施步骤

1. **建立可选装配**：在 `backend/pom.xml、backend/app/pom.xml` 规划可选账号构建配置和拟新增 `backend/account/`，通过自动装配接入，避免应用静态导入账号实现。将现有 `app/service/CapabilityService.java` 等必要通用访问契约提取至拟新增 `backend/access/`，由 `app、account` 分别依赖；在 `SchemaUpgradeRunner` 为扩展配置独立脚本与历史记录。前端构建选择账号扩展入口，无账号入口不引用该可选目录。验证物理排除扩展源码后仍能构建、启动且不读取账号表。
2. **实现账号业务**：在拟新增账号模块按 `controller、service、service/impl、model/dto、model/po、model/vo、mapper` 分层，XML 编写账号唯一性、密码摘要、状态和会话版本 SQL。拟新增 `/api/v1/auth/register、login、logout、password` 及 `/api/v1/me`；注册／登录／退出／改密均为 POST，当前用户为 GET，登录返回 Token 与到期时间，退出为 204。验证重复注册冲突、失败限流、改密校验旧密码和版本递增。
3. **实现会话与身份过滤器**：账号模块新增会话 Service 和 `OncePerRequestFilter`，按规范缓存 Token 摘要、验证用户状态／版本；加入公共启动信息入口 `/api/v1/access`，仅返回部署模式、游客开关与演示标识。公共接口精确登记，业务接口未映射权限前默认拒绝。采用身份策略装配账号／游客／无账号行为，不建立多余工厂层。验证无效 Token 为 401、Redis 故障为 503，均不转匿名放行。
4. **建立上下文生命周期**：在应用入口共享边界拟新增不可变 `RequestContext` 和 `RequestContextHolder`，过滤器设置身份、请求结束 `finally remove()`；团队／项目校验留给下一计划的路由拦截器。统一输出过滤器错误与追踪标识，验证异常、提前返回和线程复用均无身份残留。
5. **接入登录界面与 Cookie**：修改 `frontend/src/App.tsx、api/client.ts` 和拟新增账号页面／会话入口，先获取装配模式；全局 auth、me、access、teams 等接口不受项目前缀影响。请求写 Cookie、统一携带写请求防护头，并覆盖 `downloadBatch` 的独立 fetch。401 提示重登并保留草稿，503 展示认证故障；退出清 Cookie、用户缓存和旧轮询。验证根路径及 `/jmeter/` 子路径的登录、刷新和退出。

## 三、验证与完成标准

- [ ] 集成验证 Redis 会话仅存摘要键、固定到期、当前退出失效、改密／维护重置使全部旧会话失效；账号不存在和密码错误不泄露差异。
- [ ] Cookie 属性、可信 Origin、自定义头、注册／登录限流通过真实浏览器验证；JSON、multipart、批量下载请求均覆盖。
- [ ] 请求复用线程和两账号并发不串身份，认证失败不进入业务方法，日志不记录密码、原始 Token 或邀请随机码。
- [ ] 无账号构建不请求用户接口、不跳登录、不需要会话缓存；已有压测与导出仍可用。账号模式此阶段尚未完整开放业务，依赖下一计划完成授权。

按入口文档执行构建、格式与相应测试后本地提交；本阶段只在隔离测试环境启用。回退恢复匹配程序和数据备份，不通过关认证掩盖故障。前端可写 Cookie 带来的脚本读取风险须与游客计划中的原生报告隔离一起关闭，不能仅以登录成功作为整轮交付完成。
