## 一、目标与当前依据

完成团队工作台、含执行者的固定角色、超级管理员业务禁入及设置分类授权；依赖登录与共享访问契约，不做自定义角色／权限编辑器。

已核实 `app/service/impl/ProjectServiceImpl` 通过 `CapabilityService` 检查项目；`EnvironmentCapabilityService` 目前以动作后缀和维护开关判断。项目设置／公共参数已有动作校验，但场景、上传、运行和报告并未完整区分读写角色。`ProjectMapper.xml` 当前查询全部项目后由应用过滤；`frontend/src/hooks/useProject.ts` 只根据归档判断只读，均需扩展。

`StartRunDTO` 已接受 `scenarioVersionId、overrides、parameters`，执行者必须额外限制后两项；`TaskPO` 已预留 `actorType / actorId`。`SettingsPage.tsx` 当前固定请求系统信息／设置并添加项目分类，`SettingsForm` 仅区分 SYSTEM 和项目文案，需要改为类别注册和授权驱动。

## 二、实施步骤

1. **建立协作关系与团队入口**：账号模块新增团队、团队成员、团队项目绑定、项目成员的 PO／Mapper／XML。新增 `/api/v1/teams` 列表和创建、团队详情；账号模式创建项目需显式团队范围，同事务建立核心项目与团队绑定，无账号创建路径继续独立使用。借助最小通用项目目录契约协作，不反向引用 `app` 实现。验证一账号多团队、项目仅属于一个团队、所有者创建原子成功，未绑定历史项目不可见。
2. **实现固定角色与账号边界**：替换账号模式能力实现，项目角色增加执行者，按规范集中映射动作。先检查强制改密及超级管理员范围；超管只能调用人员、角色元数据、账号安全及本人接口，业务 API、下载、缓存命中和伪造成员关系均不能放行。通用能力契约支持显式资源范围，避免 `projects.manage(null)` 变成全局管理。未登记动作默认拒绝，普通团队成员不自动获得项目权限，团队继承不能被项目配置覆盖。
3. **验证范围并完成上下文**：前端 `api/client.ts` 统一增加 `X-Team-Id、X-Project-Id`；在应用路由拦截层校验头与 URL、成员关系和项目归属，再填充请求上下文。当前 `currentProjectId()` 只读项目 Hash，需配合团队导航上下文，不能从全局“最后使用团队”覆盖不同标签。下载和 `/reports/{id}/native/**` 从 URL 反查范围后同样授权。验证篡改头、头路由冲突、直接下载和多标签切换。
4. **补齐资源动作及执行者限制**：修改 `ScenarioServiceImpl、AssetServiceImpl、RunServiceImpl、ReportServiceImpl、ProjectParametersServiceImpl`，在文件、写库和进程副作用前检查动作。执行者启动只能指定已保存版本，拒绝 `overrides / parameters` 的非空覆盖及草稿执行；服务端固定任务发起人，停止／取消按 `actorId` 限本人。只读响应脱敏，批量、日志、下载、历史及缓存均受控；`ProjectMapper.xml` 等分页前筛选。验证执行者可运行但不能保存、导入、改参数、重生成报告或停止他人任务。
5. **实现设置分类权限**：扩展 `SettingsController、SettingsServiceImpl` 的类别注册与通用存储契约，账号安全类别读写仅超级管理员；其余按规范配置矩阵逐类过滤响应并独立校验保存。复用 `setting_sets、SettingsMapper.xml` 的版本校验、范围与来源，安全参数保存后下一次认证生效。账号模式不授予任何用户全局执行策略写权限；无账号仍按维护开关。验证直接请求隐藏类别、混入未授权字段、恢复默认和并发版本冲突均被正确处理。
6. **接入角色与设置界面**：修改 `App.tsx、ProjectsPage.tsx、useProject.ts、SettingsPage.tsx、SettingsForm.tsx`，复用现有布局组件。团队入口保留原卡片、层级、选中态和内部滚动；执行者显示受限运行入口，参数只读。服务端返回可见类别与可用动作，前端不固定拉取全部 `/system、settings`；超级管理员只显示人员／账号安全，普通角色的系统策略仅随已验证项目上下文只读展示。`SettingsForm` 按类别显示账号／系统／项目来源和生效说明，不能把账号安全误标为项目默认值。验证各角色、设置空态及 689px 窄窗口。

## 三、验证与完成标准

- [ ] 团队工作台与现有项目／场景页并排截图对照，卡片、侧栏、40px 层级栏及页签保持一致；长团队名、空项目和无权状态通过桌面／窄屏检查。
- [ ] 以超级管理员、团队所有者／管理员、项目管理员／编辑者／执行者／只读成员及无成员关系账号，逐项验证角色矩阵；超管拥有全局角色分配权仍不能进入项目。
- [ ] 执行者按已保存版本完成真实本机压测，不能传运行覆盖、编辑草稿或停止他人任务；未知发起人的历史任务不算本人任务。
- [ ] 按设置矩阵验证可见、只读、可写及隐藏；返回体不包含隐藏类别，直接保存、恢复默认和混入字段均不能越权。安全参数保存及重启后仍有效，既有锁定保留原到期时间。
- [ ] A 团队头搭配 B 项目、跨项目资源／附件 ID、批量混入越权项、原生 HTML 子资源、缓存命中均不能绕过；批量越权整体拒绝。
- [ ] 登录用户仅移除项目角色后，下一请求立即失去访问权；列表、计数、详情、历史版本和敏感值脱敏口径一致。
- [ ] 正常、异常和并发请求不串团队／用户；异步下载和后台压测只消费明确快照，线程池不继承身份；任务运行中退出登录或被移除成员，已提交任务仍能完成，新的人工操作重新鉴权。
- [ ] 无账号构建不依赖团队表；场景保存、真实引擎执行、报告及导出回归通过。真实压测仅访问本机测试服务。

按入口文档完成检查和本地提交。开发数据可按既有 dev 约定人工重建并绑定，暂不建设旧数据迁移工具；未建立归属的数据不自动公开。回退沿用匹配备份，保留扩展表和历史产物。
