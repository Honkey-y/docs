# 游客模式实施计划

> 状态：草稿，未执行
> 最后更新：2026-10-21
> 适用范围：账号部署内无需登录的演示体验
> 关联文档：[统一规范](../规划/账号与团队项目规范.md)、[团队项目权限计划](2026-10-21-团队项目权限实施计划.md)、[共同交付要求](../说明.md)

界面执行依据：遵守统一规范的“界面风格与复用约束”，直接复用当前项目、编辑器和报告界面，TabTin Mac 客户端仅参考细节；先保存现有页面截图和复用清单，再编写页面。

## 一、目标与当前依据

游客无需登录即可浏览固定演示项目，在页面编辑草稿，保存及真实运行等受限操作均被后端拒绝。依赖身份／权限链和独立演示产物，不改变显式无账号部署的完整能力。

目前 `frontend/src/hooks/useProject.ts` 只识别归档只读；`App.tsx` 无账号态；`ReportController.nativeFile` 和 `DownloadResponses.nativePage` 提供原生 HTML 预览；`ReportServiceImpl` 缓存失败可读取本地报告，不能把该回源方式用于认证失败。现有默认项目不能直接作为公开示例。

## 二、实施步骤

1. **准备固定样例**：在账号扩展配套开发资料中提供脱敏样例清单，由显式维护操作装载到独立项目及数据目录；外置配置指定演示团队／项目标识和游客开关。预置至少 2 个场景、2 条已完成运行及其可用报告，无需游客启动 JMeter；示例含失败统计以展示错误分布。装载幂等、与真实项目隔离，不在应用启动时重刷或覆盖数据。验证前后资源总数一致且没有真实地址、凭据或运行数据入 Git。
2. **实施游客策略**：账号模块的游客身份无需写用户表或分配登录 Token，只开放固定范围与规范中的读动作。所有写入、执行和下载在副作用前返回 `403 DEMO_READ_ONLY`；登录用户也不能直接写演示项目。公开启动信息仅返回模式、开关和演示标识，不暴露系统设置；补齐读限流。验证无会话只可读示例，携带坏 Token 则返回 401，关闭游客功能后不可匿名进入。
3. **接入页面体验**：修改 `App.tsx、ProjectsPage.tsx、ScenarioEditorPage.tsx、useProject.ts`，复用真实业务页面的侧栏、编辑页签、报告布局及统一提示样式，增加“游客体验”入口、固定团队／项目和常驻演示提示，不另做演示主题。区分归档只读、普通角色只读与游客草稿体验；游客可以编辑当前页和打开新建／运行配置弹窗，保存等按钮点击时解释限制并保留草稿。附件选择不可自动上传，草稿不存 localStorage，刷新恢复样例；不得出现假的任务提交成功。
4. **封闭旁路与报告脚本边界**：沿 `ScenarioController、AssetController、RunController、ResultImportController、ReportController` 逐一检查资源及批量入口，覆盖原生报告子资源和直接链接；数据目录不作为公开静态目录。原生 HTML 使用不开放同源能力的沙箱响应／展示，验证脚本不能读取应用 Cookie，且图表和本地资源仍可加载；必要时调整资源访问方式，不放宽会话防护。普通登录项目的直接下载和 `/jmeter/` 子路径同步回归。

## 三、验证与完成标准

- [ ] 游客页与当前场景编辑／报告页截图对照，除身份提示和受限反馈外沿用相同组件及布局；桌面／窄屏下演示提示不挤掉主要操作或破坏内部滚动。
- [ ] 无需登录，左侧仅看到演示团队，右侧仅 1 个固定项目；自行创建团队／项目数量为 0，样例场景、运行和报告可正常浏览。
- [ ] 可修改场景草稿，点击保存／另存／复制／归档／运行均被拒绝且草稿保留；刷新恢复样例，服务端数据库、文件、任务和引擎进程无变化。
- [ ] 直接 HTTP 请求覆盖上传、导入、停止、报告重试、单项／批量下载与成员管理，不能绕过；修改项目 ID 或原生资源地址不能读真实项目，超出读频率返回 429。
- [ ] 示例报告图表和统计正常，原生预览不能读 Token；用户登录后按真实角色进入自己的团队，不自动复制游客草稿或取得演示写权限。
- [ ] 移除账号扩展后的无账号完整压测与导出仍通过；停止游客开放只关闭公开体验，不删除真实数据。

按入口文档完成构建、格式和独立游客浏览器回归并本地提交；本轮账号功能整体交付前必须通过脚本隔离验收。样例更新与回退仅作用于显式配置的演示空间，不自动删除或接管已有默认项目。
