## 一、阶段一：引擎与原生报告

- 代码位置：`deep-jmeter/backend/core/`，普通 Java 核心，无账号、数据库或 Spring Security 依赖。
- 环境：JDK 21.0.9、Maven 3.9.11、JMeter 5.6.3；后端父工程锁定 Spring Boot 3.5.16 依赖管理。
- 验证命令：设置外部 `JMETER_HOME` 后运行 `mvn -B -f backend/pom.xml verify -ntp`。
- 结果：3 个测试通过、0 失败、0 跳过；包含真实临时 HTTP 服务、12 个样本/6 个失败、六类图表、CSV 公式防护、HTML ZIP 以及独立进程停止。
- 统计一致性：Web 统计树直接与原生 `statistics.json` 比较相等；图表读取原生 `graph.js` 的 JSON 数据段，不执行脚本。错误表同样直接读取原生数据。
- 边界：这是本机低负载功能验证，不作为生产压测容量。报告适配只支持锁定版本，原生输出变化须重新验证。
- Git：本阶段通过后以中文提交；提交标识以产品仓库历史为准。

## 二、阶段二：分层、持久任务与报告接口

- 代码：6个独立Controller、6个Service接口及Impl；DTO/PO/VO分包，MyBatis接口与Mapper XML，无业务Java SQL或JdbcTemplate。核心按engine、plan、report、contract分包。
- 任务：主表、配置快照、执行明细、报告头、生成历史分别存储，列表用序号游标与批量汇总读取；数据库不逐条保存压测样本。
- 升级：按用户要求移除Flyway/Liquibase，使用简单升级记录表、摘要校验与MySQL命名锁，已成功执行则跳过。dev/lease分别配置，线上参数外置。
- 自动验证：9个测试全部通过、0跳过（core 3、app 6），覆盖真实引擎API闭环、幂等冲突、旧结果导入、CSV/ZIP、原生预览沙箱、Redis故障回源、升级跳过、SQL分句和分层约束。
- 真实环境：项目专用MySQL 5.7.44库和账号；Redis 5.0.8采用RESP2。仅操作本项目库，配置文件被Git忽略，凭据不写入记录。
- 真实API验收：本地回环HTTP产生6个样本/3个失败，六类图表、484字节汇总CSV与约1MB HTML ZIP导出成功，Redis缓存可用。数据是真实测试结果，不代表容量。
- 中文备注：9张表（含升级历史）均有中文表备注，业务字段无缺失备注。
- 空表/低数据量EXPLAIN：任务领取命中`idx_tasks_queue`，游标命中`PRIMARY`，场景历史命中`idx_tasks_scenario_history`，报告领取命中`idx_task_reports_queue`；幂等唯一查询按常量索引优化。未做海量数据基准，不能保证任意规模的响应时间。
- 导出依赖：Commons CSV 1.14.1、Commons Compress 1.28.0，流式下载，统计同源。

## 三、阶段三：Web配置与界面

- 前端：TypeScript、React、Vite、ECharts，独立frontend目录，页面按场景、编辑、运行、报告和设置拆分；暖中性画布、灰侧栏、白工作区与蓝色操作。
- Web场景：DOM生成标准JMX；支持并发/循环/时长、请求排序/启停、头与正文、变量、Cookie、Basic/Bearer、响应码/正文断言、JSONPath提取和CSV附件。
- 后端自动测试：10个测试通过、0跳过。新增真实链路验证CSV中的alice/bob用户、登录提取Token、携带Token查询、Basic认证、Cookie和断言，6个样本全部成功；更新版本不改写历史运行，乐观锁冲突返回409。
- 前端：类型检查及生产构建通过；构建产物通过Maven资源处理打入后端Jar，可同源运行，不要求Node作为线上运行依赖。
- Playwright：已安装Chrome下完整流程通过，含网页新建、真实执行、六个图表、CSV与ZIP下载、原生统计预览和原生趋势页，页面无脚本异常；1440×1000与1280×800无整体横向溢出。
- 视觉检查：查看真实报告截图，修复单时间点的过宽时间轴及标签重叠；未制造趋势样本或填充虚假指标。
- 时区：真实MySQL连接与会话统一UTC，修复MySQL会话时区导致任务时间偏移；浏览器测试增加提交时间与当前时刻相差两分钟内断言。页面按Asia/Shanghai显示，原始数据与元数据存UTC。
- 设计状态：风格按参考实现并完成浏览器检查，仍可由用户审阅调整，不将实现检查写成用户已确认视觉稿。

## 四、阶段四：异常、恢复与部署边界

- 自动测试：设置JMETER_HOME后`mvn -B -f backend/pom.xml verify -ntp`通过20个测试，0失败、0跳过（core 7、app 13）。新增升级摘要冲突/失败记录、排队取消、运行中停止、部分结果、无数据、损坏CSV、路径/符号链接、密文篡改、数据密钥迁移、XML实体混淆脚本和CSV多行公式防护。
- 报告重试：损坏原始输入导致重新生成失败时，旧成功报告仍可读和导出；恢复输入后生成新批次并切换指针，目标HTTP请求计数未增长。CSV JTL的UTF-8 BOM归一化仅作用于报告输入副本，原始下载字节不变。
- 实际重启：对本次开发启动的后端做SIGKILL，保留独立引擎；新后端核实并停止旧引擎后将任务记为INTERRUPTED，36个有效样本生成部分报告，目标请求数稳定，无自动重压，临时计划已清理。
- 实际lease：从环境变量注入连接、密钥与目录，不依赖dev配置；Jar内工作台在`/jmeter`子路径通过完整Chrome流程，含新建、执行、六图、原生趋势、CSV/ZIP下载、1280×800无横向溢出与UTC时间断言。
- 单实例：第二个进程使用同一DATA_ROOT时被拒绝，原进程仍可服务。该保护不是多数据目录共享数据库或多副本高可用的支持承诺。
- 文件与配置：场景资产及配置加密，读资产时核对摘要；运行目录权限收紧，结束后删除临时明文计划/CSV，保留原始资产、JTL、日志和不可变版本。提供公开`.env.example`和中文接口说明，不存储真实凭据。
- 部署状态：已恢复dev在本机8087端口，同源Jar包含前端产物；Vite前端开发入口5173也可用。Docker镜像、编排、正式开源许可证、账号系统和完整审计不属于本轮已交付内容。
- 验证边界：本机低负载功能和索引计划验证完成，未做生产容量基准、备份整库演练或高可用故障切换；这些事项不以20个测试代替验收。
- 真实MySQL复核：升级V1/V2/V3均为SUCCESS；全部表为InnoDB，表及字段中文备注无缺失；已发布报告查询命中`idx_task_reports_available`，关联任务为`eq_ref`唯一查找。
