## 一、项目定位

将 Apache JMeter 的脚本配置、执行、结果分析和报告导出集中到通用 Web 平台，首先服务当前压测需求。首版的核心价值是：能够运行 HTTP/HTTPS 压测，在浏览器查看 JMeter 已有的趋势图与数据，并导出报告和数据。后续再拓展审计数据等能力。

**一切以开源为基准设计。** 开源核心是需求、架构、数据、接口、前端、配置、构建和验收的默认版本；公司集成是可选扩展，不作为默认环境。未来 Docker 等部署预留外置配置、持久数据、执行器和生命周期边界。详见[开源基准与部署扩展规范](规划/开源基准与部署扩展规范.md)。

文档目录独立放在 docs 根目录，与 `deepfos/` 同级，仓库分类见[文档总目录](../说明.md)。产品代码位于 `/Users/yang/Documents/project/deep-jmeter/`，前端 `frontend/`、后端 `backend/` 分开。

## 四、采用的实现方案与保留边界

- 前端使用 TypeScript、React、Vite；图表使用 Apache ECharts。
- 后端使用 Java、Spring Boot、Maven；JMeter 作为独立进程执行。
- 首版单部署实例、单执行节点，环境默认1槽、可配置有界多槽；任务存 MySQL，后端轮询领取，Redis 仅用于缓存。
- 原生 HTML Dashboard 作为结果口径基准；Web 重绘常用图表，不要求首版逐一重做原生所有图表。
- 运行中显示阶段、低频进度、日志与运行时间；完整趋势图在结果处理结束后展示。秒级实时趋势图不作为当前建议范围。
- 导入脚本保留原始文件，有限度修改标准线程组和参数；Web 配置器先覆盖基础 HTTP 场景。
- 增加已有 CSV 格式 JTL 结果导入，直接生成报告。
- 可选账号登录已完成本地验证，团队权限、人员和游客按[独立方案](账号权限/说明.md)继续；作为可移除扩展，核心不依赖账号表、登录会话或权限框架。显式无账号模式支持完整压测与报告导出，不等于账号部署中的受限游客模式。审计独立接收通用事件，具体采集范围另行确认。
- 当前使用给定开发数据库和缓存；开源发行的默认配置使用占位符与外部配置，不能包含公司地址、凭据或专属依赖。
