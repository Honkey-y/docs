## 默认速成节奏

- 总周期：6 周，约 48–60 小时；每周投入 8–10 小时。
- 每周：5 次 60–90 分钟有效会话，另留 2–3 小时完成独立任务或阶段产物。
- 每周结构：快速诊断 → 最小讲解 → 项目编码 → 测试与讲解；复习嵌入下一次会话，不单独占用整课。
- 推进规则：诊断证明已掌握的通用内容可以当场快速通过；Python 特有语义、调试、测试和阶段产物仍需证据。
- 练习比例：约 10% 讲解、70% 编码和调试、20% 测试与复盘。
- 总会话量：约 24–26 次。门禁未通过时只补对应缺口，不整章重学，也不因周次到期虚报完成。

## 会话结构

每次带练默认使用以下 60–90 分钟结构：

1. 5 分钟：读取进度，复述本次目标。
2. 5 分钟：无资料诊断、输出预测或代码阅读。
3. 最多 10 分钟：只讲当前任务需要的概念，并与 Java 对照。
4. 30–45 分钟：学习者直接改造累积项目，AI 按提示等级协助。
5. 10–15 分钟：运行、调试并增加一个失败或边界案例。
6. 5–10 分钟：学习者解释实现，AI 给出评审。
7. 5 分钟：更新进度页和下一任务。

## 每单元练习梯度

成熟课程普遍把小练习按依赖逐步串联，而不是一次讲完语法再做大项目。本计划将每个单元固定为以下梯度，难度随单元增长但顺序不变：

| 层级 | 目的 | 默认形式 | AI 边界 |
| --- | --- | --- | --- |
| A. 回忆与预测 | 暴露前置知识缺口 | 1～2 段代码阅读、输出预测或数据形状描述 | 不提供答案，先让学习者说明依据 |
| B. 概念练习 | 隔离一个新知识点 | 10～20 行核心代码，使用简单 `assert` 或单测 | 默认只给 0～2 级提示 |
| C. 实践练习 | 验证知识迁移 | 使用不同数据和规则完成工具目录业务变式 | 不复用概念题的完整实现 |
| D. 累积改造 | 建立真实项目能力 | 把本单元能力加入持续演进的 `tool_registry` | AI 可评审和补测试，不代写核心逻辑 |
| E. 讲解与变更 | 防止“测试过了但不理解” | 解释 Python/Java 差异，再应对一个小需求变化 | 通过后才记录门禁证据 |

速成模式下，若概念练习首次独立通过，可把实践练习与累积改造合并为同一任务，不再追加同类型重复题；若未通过，则只补一个针对性变式。

每个单元至少留下以下证据：

- 一次先预测后运行的记录。
- 一个独立完成的概念练习。
- 一个没有照抄答案的业务变式。
- 一个正常路径之外的失败或边界案例。
- 一段学习者自己的实现讲解，以及本单元最重要的 Python/Java 差异。

- 当前状态：已于 2026-08-27 通过，后续只在复习或发现门禁失效时回到本单元。

### `PY-01` 对象模型、基础类型与可变性

- 重点：名称绑定、对象引用、`None`、数字、布尔、字符串、可变/不可变、浅拷贝、真值。
- 常用语法：切片、字符串格式化、常用字符串方法、条件表达式。
- 练习：预测并验证别名修改结果；修复共享列表副作用；实现输入清洗和风险等级归一化函数。
- 易错点：把“变量”理解为 Java 式盒子；用 `is` 比较值；误判空容器；浮点精度。
- 门禁：能画出两个名称指向同一列表的关系，并独立通过可变性与复制的边界测试。

### `PY-02` 容器、控制流与数据变换

- 重点：`list`、`tuple`、`dict`、`set` 的选择，索引与键，遍历，成员判断，增删改查。
- 常用语法：`if`、`for`、`while`、`break`、`continue`、`range`、拆包。

- 门禁：面对嵌套容器能先写出数据形状，再选择正确访问方式；正常、空列表、缺字段、重复名称均有明确行为。

### `PY-03` 函数、参数、作用域与类型标注

- 重点：单一职责函数、返回值、位置/关键字参数、默认参数、`*args`、`**kwargs`、局部/全局/闭包作用域。

- 练习：把 `03.py` 的逻辑拆成可测试函数；设计筛选条件；演示并修复可变默认参数问题。
- 易错点：函数重载思维、默认参数只求值一次、随意使用全局状态、返回类型与异常约定不清。
- 门禁：能从空文件写出带类型标注的工具查询模块，并解释每个参数和返回约定。

### `PY-04` Pythonic 迭代与生成器

### `PY-05` 异常、资源与常用标准库

### `PY-09` SQL、事务与持久化

- 数据库基线：MySQL 5.7.44，schema `afakmv_meta`，默认 InnoDB；MCP 使用 `fh_dev_mysql`。库当前为空，学习表统一以 `py_learning_` 开头。
- 重点：表、主键、唯一约束、索引、参数绑定、连接和事务；直接使用 MySQL 原生 SQL/PyMySQL 理解边界，再迁移到 SQLAlchemy 2.0。
- 字符集：学习表显式使用 `utf8mb4`，不继承 schema 当前的三字节 `utf8` 默认值；工具名称先归一化为小写后建立唯一约束，避免 `utf8_general_ci` 的大小写语义产生误解。

- 只留印象：Alembic 的迁移职责和基本工作流；复杂查询优化留待真实场景。
- 易错点：字符串拼 SQL、会话生命周期不清、提交时机混乱、ORM N+1 问题无意识。

## 综合项目验收

- [ ] 给定合法工具信息，当创建工具时，则数据被持久化并返回稳定标识。
- [ ] 给定重复名称或非法风险级别，当创建工具时，则返回明确错误且数据库无部分写入。
- [ ] 给定启用状态、风险范围和名称关键字，当查询列表时，则筛选与排序结果稳定。
- [ ] 给定不存在的工具，当查询或变更状态时，则返回统一的不存在错误。
- [ ] 给定多个健康检查目标且部分超时，当并发检查时，则成功结果被保留、失败被分类，且总并发受限。
- [ ] 单元测试和 API 集成测试可从干净环境重复运行并全部通过。
- [ ] Ruff 和类型检查无未说明错误；如有例外，必须在文档中解释原因。
- [ ] 学习者能不看代码讲清一次请求从路由、校验、业务、仓储到数据库的路径。
- [ ] 学习者能独立增加一个小功能及其测试，AI 最多提供问题引导或局部提示。

## 速成节奏调整

- 默认六周：每周 8–10 小时，适合正常工作之外持续学习。
- 四周高强度：每周 12–15 小时，保持相同门禁，把相邻单元和项目任务进一步合并。
- 若每周少于 6 小时：现实周期应调整为 8–10 周，不用减少测试、异常和项目验收来维持“速成”名称。
- 已熟练内容允许通过诊断直接过关；必须把诊断答案、代码和运行证据写入进度页。
- 连续两次未通过同一门禁时，不重复原题，改用更小的知识缺口练习和新的业务变式，并允许排期顺延。
- 学习者明确要求“跳过并算完成”时，允许继续后续路线；该单元记为“已完成（含用户豁免）”，不得伪造门禁分数或通过证据。
