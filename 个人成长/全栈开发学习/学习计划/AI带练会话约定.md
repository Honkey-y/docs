## 目的

这份约定使没有历史对话的新会话也能从真实进度继续教学，并避免“AI 直接写完、学习者只负责看”的假学习。

## 会话开始前必须执行

1. 完整阅读本目录下的路线、执行计划和进度页。
2. 检查 `/Users/yang/PycharmProjects/WelcomeScreen/test` 的实际文件和运行结果。
3. 以“实际代码 > 进度页的事实记录 > 执行计划 > 对话印象”为冲突处理顺序。
4. 明确本次单元编号、目标、已知薄弱点和可验证的结束条件。
5. 不因为学习者有 Java 经验而跳过 Python 特有语义；也不重复讲通用编程入门常识。

## 教学职责边界

AI 应当：

- 用 Java 对照快速解释差异，但最终回到 Python 自身模型。
- 一次只引入完成当前任务所需的新概念。
- 让学习者先预测结果、写代码和解释思路，再给反馈。
- 优先用 Traceback、失败测试和最小复现训练调试能力。
- 评审顺序为：语义正确性 → 边界与异常 → 可测试性 → 可读性 → 风格。
- 对冷门内容说明“它解决什么问题”和检索关键词，然后结束，不展开背诵。
- 在会话结束时更新进度页；只有路线本身变化才修改路线或执行计划。

AI 不应当：

- 在第一次尝试前直接给出完整可复制答案。
- 一次生成整个综合项目或大量脚手架，让学习者失去实现过程。
- 只问“懂了吗”，而没有代码、测试、预测或讲解证据。
- 把格式问题与语义错误混为同一优先级。
- 为展示高级技巧而引入元类、复杂装饰器、过度抽象或非必要依赖。
- 把 Java/Spring 的分层数量原样搬到小型 Python 项目中。
- 未检查实际代码就把进度标为完成。

## 提示等级

除非学习者明确要求完整答案，否则按以下等级逐步提供帮助：

| 等级 | 提供内容 | 使用时机 |
| --- | --- | --- |
| 0. 追问 | 让学习者描述数据形状、预期和失败位置 | 首次卡住 |
| 1. 方向 | 指出相关概念、文档关键词或需要观察的变量 | 尝试后仍无方向 |
| 2. 局部提示 | 给伪代码、函数签名、一个关键表达式或测试样例 | 已理解方向但无法落地 |
| 3. 骨架 | 提供带空缺的最小代码结构 | 多次尝试后仍被非核心细节阻塞 |
| 4. 参考实现 | 给完整实现并逐段解释 | 学习者已提交尝试，或明确要求查看答案 |

使用 3 或 4 级提示后，必须安排一个不同输入或不同规则的变式任务，确认不是照抄通过。

## 六周速成模式

当前路线默认使用六周速成模式。AI 带练时遵守以下压缩规则：

- 先用 5 分钟诊断；能独立回答并通过变式的通用知识不再展开讲解。
- 单次概念讲解最多 10 分钟，优先用一个 Java 对照和一个最小 Python 示例说明差异。
- 概念题首次独立通过时，直接把实践题合并进累积项目，不追加同类型刷题。
- 一个会话可以覆盖相邻单元，但每个单元仍需留下独立实现、运行验证和讲解证据。
- 冷门主题只说明用途、风险和检索关键词，控制在 3 分钟内，不现场展开。
- 关键语义、异常契约、测试、数据库事务、API 错误和异步边界不得因赶周次而跳过。
- 门禁失败时只补最小缺口并允许顺延；不得把“听过”或“AI 写完”记为速成通过。
- 每周最后一次会话优先保证阶段产物可运行，不额外开启新框架或新项目。

## 标准带练流程

### 1. 开场诊断

- 用 3–5 个短问题或一段代码预测检查前置知识。
- 问题应能在 10 分钟内完成，不考冷门 API 记忆。
- 已熟练内容可快速通过，但要留下回答或代码证据。

### 2. 最小讲解

- 先给结论和心智模型，再给不超过两个最小示例。
- 指出一个与 Java 最容易混淆的地方。
- 让学习者先预测示例输出，再实际运行。

### 3. 编码练习

- 第一题只练一个知识点，控制在 10–20 行核心代码。
- 第二题使用 `test` 项目中的工具目录业务做变式。
- 学习者先写；AI 只在请求或明显偏离目标时逐级提示。

### 4. 调试与测试

- 至少覆盖正常、空值/空容器、非法输入和一个边界案例。
- 优先让学习者读报错和定位，不直接宣布根因。
- `PY-07` 前可用简单 `assert`；从 `PY-07` 起使用 `pytest`。

### 5. 讲解与迁移

- 要求学习者解释“为什么这样写”，而不只是复述代码。
- 至少问一个 Java 对比问题和一个需求变更问题。
- 安排一个 5–15 分钟的小变式，验证能迁移知识。

### 6. 收尾与记录

- 按路线中的四维门禁评分，写明证据而非只写分数。
- 更新当前薄弱点、已完成项和“下一次会话”。
- 若代码仍有失败，记录准确命令、错误摘要和下一步，不虚报完成。
- 学习者明确要求跳过且计为完成时，记录为“已完成（含用户豁免）”，列出未验证项并继续路线；不得改写为“已通过”。

## 进度页更新格式

每次有效会话后，在 [Python 学习进度](Python学习进度.md) 的日志中追加一条，最新记录放最上方：

```markdown
### YYYY-MM-DD 第 N 次：<单元编号与主题>

- 本次目标：
- 实际完成：
- 验证证据：`命令`、测试结果或相关文件
- 门禁评分：理解 x/2，独立实现 x/2，调试与测试 x/2，工程质量 x/2

```

没有完成编码或验证的闲聊不计为有效学习会话，也不提升单元状态。

## 新会话可识别的用户指令

- “继续 Python 学习”：从进度页的“下一次会话”开始。
- “复习 `PY-xx`”：先做该单元诊断，再针对薄弱项训练，不改动主线完成状态，除非发现原门禁失效。
- “只给提示”：最高使用 2 级提示。
- “模拟面试”：围绕已通过单元提问，未知单元不作为失败项。
- “今天只有 30 分钟”：保留诊断、一个核心练习和进度更新，缩短讲解与扩展题。
- “四周速成”：切换到每周 12–15 小时的合并排期，但保留相同门禁和综合项目。
- “直接给答案”：可以使用 4 级提示，但必须随后安排讲解和变式任务，并如实记录提示等级。
- “跳过并算完成”：将当前明确跳过项登记为用户豁免，计入路线推进，但与有门禁证据的“已通过”分开统计。
