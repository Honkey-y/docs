> 状态：草稿
> 最后更新：2026-09-06

> 关联文档：[专题说明](../说明.md)、[主案选择决策](../决策记录/2026-09-06-选择真人衣橱搭配共创社区为面试主案.md)、[项目机会池](项目机会池.md)

## 一、项目概述

### 1.1 这是一个什么项目

“真人衣橱搭配共创社区”是一个以穿搭求助为内容、以社区用户搭配为互动、以AI三维预览为差异化能力的女性穿搭社区。

用户在社区发布自己的衣物和穿搭问题，其他用户点击帖子旁的“帮她搭配”，进入搭配页面，将衣橱中的衣服拖到用户数字形象上，完成并提交搭配方案。

一句话介绍：

> 用户发布真实穿搭问题，别人用她的真实衣橱帮忙搭配，AI让她在穿或买之前先看到效果。

### 1.2 主要做什么

- 用户发布难搭单品、重要场合或购买前的穿搭求助。
- 社区用户通过拖拽衣物完成搭配，不要求具备专业造型师能力。
- AI负责衣物抠图、分类和数字形象上的效果生成。
- 搭配方案直接展示在原帖下，接受点赞、评论和发帖者采纳。
- 用户后续可以反馈是否真的采用和穿着该方案。

### 1.3 目标用户

**穿搭求助者**

- 衣服不少但经常不知道怎么搭的年轻女性。
- 有不会搭或长期闲置的单品。
- 在面试、约会、聚会、旅行前有明确穿搭需求。
- 网购前希望判断商品能否融入已有衣橱。

**搭配参与者**

- 喜欢穿搭、换装或审美创作的用户。
- 平时愿意给朋友提供穿搭建议。
- 希望低成本展示审美并获得点赞、采纳和认可。

同一个用户可以同时是求助者和搭配参与者，不构建独立的搭配师或创作者体系。

### 1.4 解决什么痛点

| 用户痛点 | 当前替代方式的问题 | 产品价值 |
|---|---|---|
| 有衣服但不会搭 | 搜索到的穿搭不基于自己的衣橱 | 让别人直接使用用户真实衣物搭配 |
| 重要场合不知道穿什么 | 问朋友缺少统一素材和效果展示 | 将求助、搭配和反馈放在一个帖子中 |
| 网购前不知道是否值得买 | 商家模特图与本人及真实衣橱无关 | 先与已有衣服组合，再决定是否购买 |
| 帮别人搭配表达成本高 | 文字建议不直观 | 拖拽衣物并由AI生成视觉结果 |
| 衣物长期闲置 | 不知道如何重新利用 | 通过社区搭配提高已有衣物使用率 |

### 1.5 项目边界

首版不做：

- 单独的搭配游戏频道。
- 搭配师后台、创作者后台和商家后台。
- 微信公众号。
- 复杂会员体系。
- 自建电商商城和二手交易。
- 试妆、护肤、色彩测试和三维妆容。
- 精确尺码、面料和商品到手效果保证。

## 二、业务概览

### 2.1 业务角色

| 角色 | 核心行为 | 获得价值 |
|---|---|---|
| 发帖用户 | 发布衣橱和穿搭求助、采纳方案 | 获得基于本人衣橱的真实搭配建议 |
| 搭配用户 | 点击“帮她搭配”、拖拽衣物、提交方案 | 获得创作乐趣、互动和认可 |
| 普通浏览用户 | 浏览、点赞、评论、收藏和分享 | 获取穿搭灵感并转化为参与者 |
| 平台运营 | 维护社区、处理举报和监控生成质量 | 保证社区内容、隐私和互动效率 |
| 电商与品牌 | 后期提供正式商品与合作活动 | 获得商品展示和成交机会 |

### 2.2 核心业务流程

1. 用户建立个人数字形象并上传部分衣物。
2. 用户在社区发布穿搭求助。
3. 帖子进入首页信息流。
4. 其他用户点击“帮她搭配”。
5. 搭配页面左侧展示求助者数字形象，右侧展示其开放衣橱。
6. 用户拖拽衣服到数字形象上，完成搭配并提交。
7. 方案展示在原帖下，与评论、点赞共同构成帖子互动。
8. 发帖者收藏、采纳或反馈方案。
9. 经本人同意，优秀方案可以被其他用户参考和复用。

### 2.4 业务发展顺序

**第一阶段：社区共创**

- 真实衣物上传。
- 发布求搭。
- “帮她搭配”互动。
- AI效果生成。
- 点赞、评论和采纳。

**第二阶段：衣橱与内容沉淀**

- 衣物逐步积累为个人衣橱。
- 搭配作品和历史方案。
- 实际穿着反馈。
- 一衣多穿等社区话题。

**第三阶段：电商与商品质量**

- 用户加入想买的候选商品。
- 候选商品与现有衣橱共同搭配。
- 通过正式合作连接购买。
- 根据真实订单、退货原因和实际穿着建立商品质量信号。

## 三、产品架构

### 3.1 用户端

底部导航只设置：

- 社区
- 发布
- 衣橱
- 我的

### 3.2 社区首页

首页就是社区信息流，不建设独立游戏入口。

**帖子内容**

- 用户头像和基础资料。
- 穿搭问题与使用场景。
- 必须使用的单品。
- 用户公开的衣橱范围。
- 已提交的搭配方案。

**帖子互动**

- 点赞
- 评论
- 收藏
- 帮她搭配

点击“帮她搭配”后进入该帖的搭配页面。

### 3.3 帮她搭配页面

**页面布局**

- 左侧：求助者三维数字形象。
- 右侧：求助者本次开放的衣橱。

**核心操作**

- 拖拽上衣、下装、鞋包和配饰到数字形象上。
- 切换、撤销和重置衣物。
- 查看AI生成的搭配效果。
- 填写简短搭配说明。
- 提交到原帖。

MVP若无法稳定实现真正可旋转的三维服装仿真，可以先用多角度数字形象验证交互，但用户界面和产品目标保持一致。

### 3.4 发布求搭

- 选择或创建个人数字形象。
- 从衣橱选择本次公开的衣物。
- 指定必须搭配的单品。
- 填写场合、风格和限制条件。
- 设置数字形象与衣物的可见范围。
- 发布到社区。

### 3.5 我的衣橱

- 上传衣物。
- AI抠图和基础分类。
- 编辑衣物信息。
- 设置公开或私密。
- 查看衣物被使用的搭配方案。
- 后期加入候选电商商品。

首版不要求一次上传完整衣橱。用户可以在每次求助时逐步积累。

### 3.6 我的

- 我的求搭。
- 我提交的搭配。
- 被采纳记录。
- 点赞与收藏。
- 基础个人资料。
- 数字形象与隐私设置。

### 3.7 平台管理后台

- 用户管理。
- 社区帖子管理。
- 评论、举报和内容审核。
- 衣物素材管理。
- 数字形象管理。
- AI生成任务与失败处理。
- 基础运营数据。

不建设独立的搭配师、创作者和商家后台。

## 四、商业模式与用户增长

### 4.1 商业模式

首版核心功能免费，先验证社区互动，不建设重会员体系。

**AI生成付费**

- 提供有限免费生成次数。
- 高质量、多角度或快速生成按次收费。
- 生成失败不扣费或返还次数。

**电商佣金**

- 用户将想买的商品加入本次搭配。
- 搭配完成后跳转正式电商平台购买。
- 平台通过官方合作获得佣金。
- 商业商品必须明确标识，不因佣金高低获得自然排序优势。

**品牌合作**

- 品牌围绕指定单品发起社区搭配话题。
- 商业内容与普通求搭明确区分。
- 品牌可以获得经用户授权的搭配内容和聚合反馈。

**二手导流**

- 对长期闲置衣物生成搭配历史和二手发布资料。
- 与正式二手平台合作，不在首期自建交易。

### 4.2 用户增长

**种子内容**

- 邀请穿搭爱好者、服装专业学生和普通女性用户发布真实求搭。
- 运营初期人工保证帖子获得有效搭配。
- 集中做“拯救难搭单品”“面试穿搭”等话题。

**社区互动转化**

- 浏览用户通过“帮她搭配”从消费内容变为生产内容。
- 搭配门槛控制在拖拽衣物和一句说明。
- 发帖者采纳后，搭配者获得作品和被采纳记录。

**好友分享**

- 求搭帖子可以分享给微信好友。
- 好友点击链接即可帮忙搭配。
- 参与后再引导其发布自己的求搭。

**内容传播**

- 将被采纳方案生成“难搭单品被救活”的分享卡。
- 经本人同意后展示搭配前后效果。
- 热门搭配可以成为其他用户的参考模板。

### 4.3 增长闭环

> 用户发布真实求搭 → 其他用户点击帮她搭配 → AI生成效果 → 方案进入原帖 → 点赞评论与采纳 → 结果被分享 → 新用户参与或发布求搭。

## 五、MVP与验证

### 5.1 MVP功能

- 社区信息流。
- 发布求搭。
- 衣物上传、抠图和分类。
- 个人数字形象。
- 帖子点赞、评论、收藏和“帮她搭配”。
- 左侧数字形象、右侧衣橱的搭配页面。
- 拖拽、生成和提交方案。
- 发帖者采纳与反馈。
- 我的求搭、我的搭配和被采纳记录。
- 必要的内容审核和隐私设置。

### 5.2 六周安排

| 时间 | 目标 |
|---|---|
| 第1周 | 用户访谈、原型和三维交互可行性验证 |
| 第2周 | 社区、发布、帖子详情和衣橱 |
| 第3周 | 帮她搭配页面与拖拽交互 |
| 第4周 | 数字形象和AI生成接入 |
| 第5周 | 方案提交、采纳、评论与隐私 |
| 第6周 | 种子用户试运营、数据复盘和继续决策 |

### 5.3 核心指标

- 发布求搭完成率。
- 获得有效搭配的帖子比例。
- “帮她搭配”点击到提交转化率。
- 首个搭配方案等待时间。
- 搭配方案收藏和采纳率。
- 求助者再次发布率。
- 搭配者再次参与率。
- 实际穿着反馈率。
- AI生成成功率、耗时和单次成本。
- 隐私与社区安全事件。

### 5.4 关键风险

| 风险 | 应对 |
|---|---|
| 社区无人搭配 | 种子用户、人工补位、集中话题，必要时AI方案兜底 |
| 上传衣橱成本高 | 每次只上传本次需要的少量衣物并逐渐积累 |
| 三维效果不真实 | 定位为搭配示意，不承诺面料、尺码和到手效果 |
| 人体与照片隐私 | 原始照片默认私密，公开数字形象需单独授权 |
| 身材羞辱或恶搞 | 举报审核、禁止身体评分、用户控制可见范围 |
| 商业推荐损害信任 | 已有衣物优先，商业内容标识，佣金不影响自然排序 |
| 功能再次扩张 | 新功能必须服务社区求搭闭环，否则不进入MVP |

## 六、未决问题

1. MVP采用真正三维模型还是多角度数字形象。
2. 首批用户从职场女性、穿搭初学者还是高校用户进入。
3. 用户是否愿意公开数字形象，还是只向帮助者临时开放。
4. 搭配者参与的主要动力是好玩、帮助、作品还是社交认可。
5. 电商商品在何时、通过哪种正式合作方式进入。
6. AI生成质量和成本能否支持高频社区互动。
