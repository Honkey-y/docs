# 商业模式与用户增长

> 状态：草稿
> 最后更新：2026-09-07
> 适用范围：真人衣橱搭配共创社区
> 关联文档：[项目立项说明书](真人衣橱搭配共创社区立项说明书.md)、[产品功能与技术架构](产品功能与技术架构.md)

## 一、商业模式

### 1.1 商业原则

- 社区浏览、发布求搭、帮她搭配、点赞和评论保持免费。
- 付费点设置在有额外成本或明确增值的能力上。
- 平台优先帮助用户使用已有衣服，不能为了佣金诱导购买。
- 商业商品、品牌合作和佣金关系必须明确标识。
- 前期先验证社区互动和用户价值，不建设复杂会员体系。

### 1.2 价值交换

| 参与方 | 提供价值 | 获得价值 |
|---|---|---|
| 穿搭求助者 | 真实衣橱、具体问题、采纳和穿着反馈 | 个性化搭配方案和AI试穿效果 |
| 搭配参与者 | 审美判断、搭配方案和社区内容 | 创作乐趣、互动认可和被采纳记录 |
| 品牌与商家 | 商品、佣金、活动预算和商品信息 | 商品曝光、搭配内容和成交机会 |
| 平台 | 社区、AI能力、匹配、内容治理和交易连接 | AI增值收入、佣金和品牌收入 |

### 1.3 收入来源

#### AI生成付费

- 提供少量免费试穿次数。
- 高清、多角度或快速生成按次收费。
- 生成失败不扣费或返还次数。
- 不单独建设复杂会员中心。

#### 电商佣金

- 用户上传或导入想购买的商品。
- 社区将商品与用户已有衣橱搭配。
- 用户通过官方链接返回电商平台购买。
- 平台按成交获得佣金。

电商推荐必须：

- 优先使用用户已有衣服。
- 展示衣橱中是否存在相似替代品。
- 明确标识佣金和商业合作。
- 不因佣金高低改变自然搭配排序。

#### 品牌合作

- 品牌围绕指定单品发起搭配话题。
- 用户使用品牌商品和真实衣橱完成搭配。
- 品牌获得经授权的搭配内容和聚合反馈。
- 平台收取活动服务费、内容合作费或技术服务费。

#### 二手平台导流

- 对长期闲置衣物生成搭配记录和发布资料。
- 用户跳转合作二手平台完成交易。
- 平台获得导流或服务收入。
- 平台首期不自建二手支付、物流和纠纷处理。

### 1.5 商业化顺序

| 阶段 | 商业重点 |
|---|---|
| MVP期 | 核心功能免费，仅测试AI生成付费意愿 |
| 社区成长期 | 高质量生成按次付费 |
| 交易验证期 | 接入一家电商或少量品牌，验证成交佣金 |
| 规模化阶段 | 品牌搭配活动、商品反馈和商业服务 |
| 生态阶段 | 二手导流及其他服装生命周期服务 |

### 1.6 单位经济模型

> 单次成功共创成本 = AI处理与生成成本 + 图片与3D资产存储 + 社区审核与运营 + 用户激励 + 客服成本。

成本控制方式：

- 拖拽过程使用低成本即时预览。
- 只对用户选中的方案生成高质量效果。
- 相同衣物素材和数字形象复用处理结果。
- 持续监控生成成功率、单次成本和用户付费意愿。

## 二、用户增长

### 2.1 增长难点

平台同时需要：

- 有真实穿搭问题的求助者。
- 愿意帮助别人搭配的参与者。

如果帖子无人搭配，求助者会流失；如果没有真实任务，搭配者也没有参与动力。

### 2.2 冷启动策略

#### 聚焦单一话题

首期只做“拯救难搭单品”，不同时覆盖全部穿搭需求。

示例：

- 这条裙子买了半年，怎么搭才能穿出去？
- 明天面试，用这些衣服帮我搭一套。
- 不买新衣，用现有衣橱完成三套搭配。

#### 准备种子用户

首批邀请：

- 喜欢穿搭的普通用户。
- 服装、设计和艺术专业学生。
- 喜欢换装游戏的用户。
- 小型穿搭博主及其粉丝。

种子用户不需要独立后台，直接使用普通社区账号。

#### 保证帖子得到回应

- 初期控制每日求助数量。
- 运营人员主动将求助转发给匹配用户。
- 对无人参与的帖子提供人工或AI兜底方案。
- 集中在固定时间开放主题求搭，提高供需密度。

### 2.3 核心增长循环

下图展示一次求搭如何转化为新内容和新用户。

~~~mermaid
flowchart LR
    A[用户发布真实求搭] --> B[其他用户点击帮她搭配]
    B --> C[拖拽衣物并生成效果]
    C --> D[方案提交到原帖]
    D --> E[点赞、评论与采纳]
    E --> F[生成可分享的搭配结果]
    F --> G[好友或外部用户进入]
    G --> H[参与搭配或发布求搭]
    H --> A
    E --> I[搭配者获得被采纳记录]
    I --> B
~~~

### 2.4 拉新方式

#### 好友求助分享

- 用户将求搭帖子分享给微信好友。
- 好友点击后直接进入“帮她搭配”。
- 完成搭配后再引导好友注册和发布自己的求搭。

#### 结果内容分享

- 将被采纳方案生成“难搭单品被救活”的分享卡。
- 展示衣物组合、搭配者和采纳结果。
- 是否公开数字形象由求助者决定。

#### 社区话题

- 拯救闲置单品。
- 一衣多穿。
- 面试穿搭。
- 旅行穿搭。
- 禁止买新衣挑战。

话题直接存在于社区，不建设独立游戏频道。

#### 外部种子渠道

- 高校女性社群。
- 白领兴趣群。
- 穿搭、收纳和二手社群。
- 小型穿搭博主和普通用户朋友圈。

### 2.5 用户留存

**求助者留存**

- 收到新的搭配方案。
- 方案被点赞和评论。
- 重要场合前再次求搭。
- 衣橱逐渐积累后，下一次发布成本降低。
- 反馈实际穿着后获得新的改进建议。

**搭配者留存**

- 搭配方案被收藏和采纳。
- 个人资料保留搭配作品。
- 获得被采纳次数和风格标签。
- 持续收到适合自己的求搭内容。
- 参与周期性社区话题。

### 2.6 轻量激励

- 完成有效搭配获得基础积分。
- 被收藏或采纳获得额外积分。
- 用户确认实际穿着获得更高权重。
- 积分用于兑换AI生成次数或优先求搭。
- 首期不支持积分提现，不建设复杂等级体系。

### 2.7 核心指标

**北极星指标**

> 每周成功完成的穿搭共创数。

一次成功共创至少包括：

- 用户发布真实求搭。
- 至少一名其他用户提交有效搭配。
- 发帖者完成查看、收藏或采纳。

**增长指标**

| 环节 | 指标 |
|---|---|
| 求助供给 | 求搭发布量、发布完成率、再次发布率 |
| 搭配供给 | “帮她搭配”点击率、方案提交率、搭配者留存 |
| 社区流动性 | 有效回复率、首个方案等待时间、平均方案数 |
| 用户价值 | 收藏率、采纳率、实际穿着反馈率 |
| 传播 | 分享率、分享访问率、访客参与率、邀请注册率 |
| 商业化 | AI付费率、商品点击率、成交率、退货和保留反馈 |

## 三、阶段目标

### 0到1阶段

- 验证用户是否愿意发布真实衣橱问题。
- 验证其他用户是否愿意帮忙搭配。
- 验证AI效果是否提高方案采纳率。

### 社区增长阶段

- 提高帖子有效回复率。
- 降低首个搭配方案等待时间。
- 建立求助者与搭配者的双向转化。
- 形成可复用和可分享的社区内容。

### 商业验证阶段

- 测试高质量AI生成付费。
- 接入少量正式电商商品。
- 验证搭配是否影响购买和商品保留。
- 在不损害用户信任的前提下测试品牌合作。

## 四、风险控制

| 风险 | 应对 |
|---|---|
| 无人参与搭配 | 控制任务量、种子用户、人工分发和AI兜底 |
| 低质量搭配泛滥 | 采纳反馈、举报审核和低质量限流 |
| 商业推荐过多 | 已有衣物优先、商业标识、佣金不影响排序 |
| AI生成成本过高 | 低成本预览，用户选中后再生成高清结果 |
| 商品图片与实物不符 | 明示AI效果为搭配示意，结合真实购买反馈 |
| 功能过度扩张 | 商业化功能必须建立在社区共创闭环成立之后 |
